# 50 种食材、我的小馆精简与入口配置

## 本次已实现

「我的小馆」去掉当前风格说明、玩家身份卡、云端存档卡、手动同步按钮以及自动保存/版本提示；保留地区、图鉴、页面风格、云端地域榜和继续游戏，缩短弹框。自动存档、自动云同步和存档冲突处理继续使用原流程。

23 种原有食材与此前确认的 27 种新增食材全部加入游戏和图鉴，共 50 种。新增第一格使用秋葵替换原先不采用的肉类草稿。图片沿用已确认的手绘稿，按固定单元格打包，保留原有米白底；没有重绘原有食材。新增图集 960×800，281,726 字节。

新局各关从 50 种中分别抽取 3 / 4 / 10 种，保留牛肉与羊肉互斥规则。旧存档未带 `ingredientPoolVersion` 时按原 23 种抽取逻辑校验和还原；新局记录 `ingredientPoolVersion: 2`。牌阵、翻锅、撤回、复活和食材守恒沿用原规则。

## 后台在哪里修改

使用项目已有的**微信开发者工具 → 云开发 → 数据库**，确认环境为 `cloud1-d2gc9q7cobffff893`。

1. 新建集合 `hotpot_config_dev`，权限设为「仅管理端可读写」。客户端通过云函数读取，不直接操作集合。
2. 新建文档，指定 `_id` 为 `runtime`，填入以下数字字段：

```json
{
  "_id": "runtime",
  "collectionHeadingTaps": 6,
  "collectionIngredientTaps": 3
}
```

| 字段 | 对应操作 | 有效值 |
|---|---|---|
| collectionHeadingTaps | 先点击「小馆珍藏」标题的次数 | 1～99 的整数 |
| collectionIngredientTaps | 再点击「食材图鉴」页签的次数 | 1～99 的整数 |

例如改为 8 和 4，就是先点标题 8 次，再点图鉴页签 4 次。字段类型必须是数字，不能写成字符串。缺失或非法字段分别使用默认值 6 和 3。

客户端在云连接建立时，以及进入「我的小馆」时刷新配置。保存后台后重新进入游戏可以确定读到新值；打开中的图鉴固定使用进入该次图鉴时的次数，避免配置更新打断正在输入的序列。关闭图鉴或切到成就会中断当前点击序列。

未配置文档、断网或读取失败时使用默认值/本次会话最后一次有效配置，不阻塞游玩。`config` 云函数操作只读，客户端传入的同名字段不会写入数据库。隐藏入口仍为原有本地调试菜单，点击次数不是管理端身份认证。

## 首次启用与部署

本轮修改包含新的云函数读取能力和 50 种食材的存档校验。**需要先将本地 `app/HotPot/cloudfunctions/hotpotPlayerDev` 上传部署到上述开发环境，再使用新版客户端。** 上传时安装云端依赖；新增 `RuntimeConfig.js` 与 `runtime-config.js` 必须随函数上传。

本轮不自动变更云端数据库或部署云函数。后台位置与配置结构已经确定；完成一次部署和文档初始化后，以后调整点击次数只需编辑该文档，不需要重新编译客户端。

对局协议由 4 升为 5；旧云函数会被新版客户端识别为需要升级，避免把新食材局交给旧规则校验。
