# 锅里捞啥 V0.1

基于 **Cocos Creator 3.8.8 + TypeScript** 的竖屏叠层点选三消 MVP。

当前玩法、三关配置与最近改动见 [仓库 README](../../README.md)。跨电脑接手可参考 [设计与开发交接](../../doc/锅里捞啥-设计与开发交接.md) 和 [2026-09-28 改动记录](../../doc/锅里捞啥-改动记录-2026-09-28.md)；这些历史文档中的关卡数、层数和道具开放条件以当前 README 与源码为准。

## C 款界面与 23 种食材（2026-10-26）

成功、失败、图鉴、档案及其他弹框统一采用 C「锦绣食盒」的红漆木框、奶油纸内衬与细金边；顶部入口、底部操作和道具按钮同步调整，道具次数耗尽显示灰褐色，后门开启无限时显示 `∞`。成功与失败使用独立的铜火锅／满托盘插画。图鉴内容为可滚动的两列卡片，档案分为身份、地区和存档三个分区。

保留原 13 种，新增毛肚、鸭血、土豆、蟹棒、宽粉、午餐肉、海带结、羊肉、乌鸡卷、山药，总计 23 种。新开局从整个池中不重复抽取：第一关 3 种、第二关 4 种、第三关 10 种。**牛肉与羊肉不出现在同一局**。翻锅不重新抽取种类；重开重新抽取，继续存档保留食材组合。

新局保存 `ingredientSeed`，种类、配比与原有 `layoutSeed` 一起可复现；校验器按食材种子验证完整配比，拒绝外来食材和牛羊混入。没有食材种子的旧存档继续使用原 13 种配比及原牌阵。对局协议升级至 **4**；客户端和 `cloudfunctions/hotpotPlayerDev` 必须一起更新，旧云函数连接时保留本机记录并提示升级。

新增图集：`expanded-atlas.png`（4×2，最后一格空）、`extra-meat-yam-atlas.png`（3×1，羊肉／乌鸡卷／山药）和 `modal-emblems-c.png`（2×1，成功／失败）。新增食材每格 256px，弹框插画每格 384px，保留 Alpha 透明，适配小游戏包体。`panel-skin-c.png` 和 `button-skins-c.png` 通过九宫格拉伸保留 C 款的漆木角花、米纸和金属边缘。生成原图与设计记录放在仓库 `design/ui-c-ingredients/`，`tools/prepare-ui-art.cjs` 借助 sharp 导出打包图片。

原 12 张独立备用食材图片及元数据移至 `assets/art-archive/ingredients-legacy/`，现有 `handpainted-atlas.png` 和独立茶树菇 `jzg.png` 保持不变；图集异常时显示食材名称备用牌面，归档图片不进入 resources 包。

微信启动使用 `build-templates/wechatgame/first-screen.js`：只初始化画布并显示暖色底，不加载 Cocos 标志、口号或进度条，也不等待动画帧。引擎插屏时长为 0。GUI 与 CLI 的构建收尾会同步首屏模板和插屏设置，旧的编辑器构建任务也会应用。底部操作及三个道具按钮的图标、名称、次数已向内容区收拢，留出边框装饰间距。

## 运行

1. 使用 Cocos Creator 3.8.8 打开本目录。
2. 等待首次资源导入完成。
3. 打开 `assets/scene/main.scene`，点击预览。

顶部不提供选关按钮，通关后点击“下一关”依次推进。发亮牌可点击，变暗牌表示仍被上层覆盖。

## 玩法与关卡

食材进入七格托盘后自动与同类归并，三个同类自动消除。棋盘和托盘全部清空时获胜；结算三消后，托盘仍有七张未消除的牌时失败。

| 关卡 | 名称 | 方块数 | 层数 | 食材种类 | 道具 |
| --- | --- | ---: | ---: | ---: | --- |
| 1 | 开锅尝鲜 | 18 | 2 | 3 | 无 |
| 2 | 热锅练手 | 30 | 2 | 4 | 每种一次 |
| 3 | 千层盛宴 | 888 | 37 | 10 | 初始每种一次，阶段奖励可补充 |

第三关固定 888 张、37 层、每层 24 张。新开局生成四簇、双环或菱形分布，重试强制切换到与刚才不同的整体牌阵，食材位置也随机。各组逐层交替半步环形牌位，下层每张至少被紧邻上一层的两张覆盖，有遮挡关系的任意两张牌重叠面积至少 20%，同层无重叠。每层食材按完整三张组生成，存在从上到下逐层清空的通关路径。

`createLevel(2)` 随机生成第三关，传入第二参数可复现牌阵；第三参数可传上一局牌阵种子，使新牌阵切换类型；第四参数为食材种子。显式传牌阵种子而不传食材种子时走旧存档兼容路径。牌阵种子为 0 时复现旧版固定布局，1～2147483646 保留上一版六组布局，2147483647～4294967292 使用新版三种牌阵。存档携带 `layoutSeed` 与 `ingredientSeed`，继续游戏保留牌位、遮挡及食材组合。

撤回恢复上次拿牌前状态；炸随机消除棋盘上一种食材的三张或六张（可包含被遮挡的牌）；翻锅只打乱剩余食材种类，不改变牌位和层级。炸和翻锅会清除旧撤回记录，各道具开局各一次，第三关可通过阶段奖励补充，重开本关后恢复初始次数。

炸仅移除命中的牌节点，保留其余牌及食材图片，只重画遮挡状态发生变化的牌；整盘遮挡刷新使用按 ID 查询，避免第三关每炸一次都重建数百张牌。第三关顶部只计算阶段倒计时，省去未显示的可拿牌数量统计。

三消触发时立即从逻辑托盘移除三张，动画单独播放，因此消除动画期间可以继续点击，不会因动画尚未结束而误判满格。单张牌飞入托盘的约 0.28 秒仍会短暂锁定输入。连续三消不会互相修改托盘；重开、切关和撤回会清理消除特效。

三关每局均有一次免费复活：首次满格后点击“免费复活一次”，托盘前三张进入寄存区，释放三格。点击寄存食材取回参与三消，棋盘、托盘、寄存区全部清空才获胜。寄存区出现时棋盘略微缩小，为寄存区留出空间。复活不删除食材、不补充道具，并清空此前的撤回记录；之后的撤回会同时恢复托盘和寄存区，但不恢复复活次数。重开或切关重置次数，无需接入广告。

## 开锅阶段与翻锅

第三关开锅阶段：每实际消除 100 块随机补充一次撤回、炸或翻锅，共八档奖励。三消和炸均计入，托盘与寄存区不计入；撤回不重置已领取门槛，重开重置。第三关顶部仅显示“距离下一次获取道具还有X个”，隐藏总数和已消数量；八档奖励领完后改为完成提示。翻锅时全部剩余棋盘牌（含被遮挡牌）聚拢、交错混洗，再散回原牌位，动画约1.38秒，期间锁定输入；旧关卡回调不会影响新关卡。

## 隐藏后门页

打开顶部“图鉴”，点击“小馆珍藏”标题 6 次，再点击“食材图鉴”页签 3 次，弹出“后门设置”。过程中没有计数、解锁或剩余次数提示。切到“我的成就”、进入食材详情或退出图鉴会中断未完成的序列；进入后门后再次打开仍需完整操作。

后门页可直接进入三关中的任意一关，点击当前关卡则重开本关。第二、三关可分别切换撤回、炸、翻锅的“正常次数 / 无限使用”，第一关不提供道具开关。无限模式的道具角标显示 `∞`，实际使用不扣正常次数，关闭后恢复原有次数；仍需满足撤回快照、炸的目标与翻锅剩余牌数等条件，并遵守动画锁和结算状态。

三关均提供“本关只留3个相同食材”：清空托盘与寄存区、清除旧撤回记录，将当前棋盘变为只剩同类三张，点击取完即可正常通关。保留关卡、牌阵、食材总配比、无限开关和已用复活状态；第三关补齐已达到的阶段奖励，重复操作不重复领奖。该残局按正常对局保存，退出后可继续；已结算的本关也可转为三张残局重新测试通关。

无限开关仅当前这局、当前运行期间有效，重开、切关、恢复存档或跨日重置后关闭；不写入本地或云端玩家存档。通过后门进行的选关和后续对局进度仍按现有规则保存。

## 验证

在本目录运行：

```powershell
node .\tools\validate-levels.cjs
node .\tools\validate-tray-animation.cjs
node .\tools\validate-player-save.cjs
node .\tools\validate-collection-ui.cjs
```

脚本使用 Cocos Creator 自带的 TypeScript，默认安装目录为 `C:\ProgramData\cocos\editors\Creator\3.8.8`。如果安装在其他位置，先设置 `$env:COCOS_CREATOR_388 = '你的 Creator 3.8.8 安装目录'`。

- 关卡验证：三关数量与牌数、32 个种子的随机牌阵与完整可解路径、37 层布局、同层无重叠、双块遮挡、至少 20% 覆盖面积、棋盘边界及同种子复现。
- 存档验证：随机牌阵种子和遮挡关系完整恢复、拿牌和翻锅后形状不变、无种子旧存档兼容、异常种子拒绝，以及本机与模拟云端同步。
- 动画验证：第七张触发三消、连续消除时立即释放位置、旧回调不修改新托盘、真实满格判负与清空获胜。动画使用模拟时序验证，视觉效果仍需在 Creator 预览中检查。
- 复活验证：食材数量守恒、重复请求只生效一次、寄存取回与撤回、第二次失败不能复活，以及寄存区清空后才获胜。
- 阶段与翻锅验证：跨百奖励、八档总数、防止撤回重复领奖、未消除食材不计数、动画期间防重复使用及切关回调隔离。
- 后门验证：无提示的 6+3 触发顺序、错误顺序与退出重置、选关、三个独立开关、正常次数为零时连续使用、动画与结算限制、重开与切关重置，以及存档仍符合原校验规则。
- 炸性能回归：888 张牌的连续炸不会重建棋盘，保留未命中的牌及图片节点，遮挡查询使用 ID 索引，只重画状态变化的牌。
- 三张残局验证：三关的进行中、失败与通关状态均可设置，清空托盘与寄存区，保留牌阵与种类配比，奖励不重复，真实存档校验与恢复通过，最后三张可取且正常触发通关。

## 微信小游戏

当前 CloudBase 开发分支请使用 `tools/build-cloud-dev.ps1`，生成独立的 `build/wechatgame-cloud-dev`；默认发布输出 `build/wechatgame` 在此分支受保护。身份、地区、存档、权限与部署步骤见 [CloudBase 玩家开发交接](../../doc/CloudBase玩家身份与云存档-开发交接.md)。云函数目录位于 `cloudfunctions/hotpotPlayerDev`，不进入小游戏包；顶部新增“档案”入口。

保存并关闭 Cocos Creator 后，在 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-wechat.ps1 -Open
```

脚本会生成 `build/wechatgame/`，并调用本机微信开发者工具。若工具的“服务端口”已开启，脚本会自动载入项目；否则会打开入口页，此时选择“导入项目”并选中该构建目录。默认使用本项目已有 AppID `wx943cc2d81ec6f820`，可通过 `-AppId` 覆盖。脚本采用发布构建，等待 Creator 成功退出后检查完整目录必须小于 4,000,000 字节。

2026-09-30 已裁剪未使用的物理、骨骼动画、瓦片地图等引擎模块；未引用的 `hotpot-bg.jpg` 和 `hotpot-corner.png` 已连同 UUID 元数据移至 `assets/art-archive/`，不再进入 resources 包。当前背景、标题、食材、备用食材和音频保持原样。重新构建前请关闭并重新打开 Creator，以加载更新后的引擎模块配置。

## V0.1 内容

- 720 × 1520 竖屏设计尺寸，短屏完整缩放显示，长屏扩展顶部和底部空间
- 纸纹背景直接作为棋盘底，奶油色立体食材牌、木质七格托盘、带文字和次数的道具按钮
- 13 种可轮换食材的透明 PNG 美术，单关使用 3～10 种
- 第一、二关 2 层，第三关 37 层，按实际几何重叠判定遮挡
- 点击进入托盘、同类自动归并、三消立即释放槽位，并独立播放消除与补位动画
- 7 格托盘、胜利/失败面板、带二次确认的重新开始
- 第 2 关起提供撤回、炸、翻锅道具，开局各 1 次，第三关阶段奖励可额外补充
- “炸”从棋盘剩余食材中随机选一种：至少 6 张消除 6 张，3～5 张消除 3 张；不足 3 张不参与选择，无可选种类不扣次数，不影响托盘
- 3 个关卡：开锅尝鲜（18 张，无道具）、热锅练手（30 张，有道具）、千层盛宴（888 张，有道具）
- 第 3 关为 37 层，每层 24 张，重试切换四簇、双环或菱形分布并重新排列食材；每张下层牌至少被紧邻上一层的两张牌覆盖，每对遮挡重叠面积至少 20%
- 首次触摸后循环播放背景音乐，并播放三消、过关和失败音效

订单、火锅特殊牌、存档和广告未纳入 V0.1。原 3D Hello World 素材已不被主场景引用，不会进入按场景引用构建的正式包。
