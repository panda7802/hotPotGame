# 每日进入与第三关失败规则

2026-10-23，开发分支 `codex/cloudbase-player-save`。

- 按设备本地自然日判断。每天第一次进入从第一关全新棋盘开始；同一天再次进入继续当天存档。
- 游戏在后台跨天，返回前台也会清除上一天的棋盘、托盘、寄存及本局道具状态，从第一关开始。
- 第三关失败后保留失败弹窗，点击“重试第三关”仍从第三关开始。四簇、双环和菱形分布三种牌阵间切换，连续重试保证整体类型不同，食材位置也随种子随机。主动重新开始第三关采用相同规则，固定随机数也不会导致连续两局同形。
- 免费复活继续当前牌阵；同一天恢复第三关存档时使用保存的布局，失败存档恢复后仍可选择复活或重试。第一、二关的失败、复活及重试规则保留。
- 地区、玩家身份、图鉴、成就和历史最好成绩不因每日重置或重试而清空。

`PlayerState.playDate` 保存对局所属日期，格式为 `YYYY-MM-DD`。旧存档没有日期时按新一天处理，先保留可确认的永久记录，再清除旧棋盘。同一天在其他设备读取已标记当天的云存档可继续进度。

客户端在首次加载、后台返回、账号重新连接和冲突解决时应用日期规则。冲突选择上一天的云端存档也不会恢复旧棋盘；延迟到达的上一天同步响应不会覆盖新一天的本机棋盘。日期来自设备时间，不提供服务器校时或防修改设备日期机制。

## 更新顺序

1. 先部署本分支最新 `hotpotPlayerDev` 至 `cloud1-d2gc9q7cobffff893`，远程安装依赖。本地云函数源码和 `exports/cloudbase-player-dev/hotpotPlayerDev.zip` 已同步更新。
2. 实际小游戏调用 `load` 应返回 `ok: true`、`progressVersion: 1` 和 `playSessionVersion: 3`。新版种子范围区分三种新牌阵和旧六组牌阵，无种子及旧种子存档仍按旧算法恢复。
3. 再在 Cocos 正常构建 `wechatgame-cloud-dev`，重新加载开发构建验收。

旧函数会丢弃新增日期或拒绝新版牌阵种子，因此新客户端检测不到当前 `playSessionVersion: 3` 时暂停云同步并提示“请先更新云函数再同步每日关卡”；本机游戏仍可进行，已有账号私有缓存不会被覆盖。本次只修改代码、准备本地函数包和执行测试，没有操作编辑器、重新构建或远程部署。

## 验证

存档测试覆盖本地午夜、跨年、同日恢复、旧档迁移、日期校验、离线重置、冲突的两种选择、跨午夜延迟响应以及永久记录保留。游戏测试验证第三关失败后停留当前关、重试保存新第三关布局、随机结果重复时仍更换布局、同日恢复保持布局、第一二关重试及后台跨天返回规则，并回归消除动画和稳定存档。
