# 火锅叠叠消：项目文件说明

本文说明仓库内与《火锅叠叠消》有关的目录和文件。当前游戏使用 **Cocos Creator 3.8.8 + TypeScript**，工程目录为 `app/HotPot`。

## 1. 仓库根目录

| 路径 | 作用 |
| --- | --- |
| `README.md` | 仓库入口说明，目前只记录项目名称和用途。 |
| `doc/火锅叠叠消-游戏方案.md` | 原始玩法、界面、关卡和版本需求，是产品需求基准。 |
| `doc/火锅叠叠消-V0.1可行性审核.md` | 对原始方案的可行性审核、V0.1 范围和风险说明。 |
| `doc/火锅叠叠消-项目文件说明.md` | 本文，解释工程中各文件和目录的用途。 |
| `app/HotPot/` | 可以直接由 Cocos Creator 3.8.8 打开的游戏工程。 |

## 2. 工程根文件

| 路径 | 作用 |
| --- | --- |
| `app/HotPot/package.json` | Cocos 工程身份信息和 Creator 版本声明。 |
| `app/HotPot/tsconfig.json` | TypeScript 配置；继承 Creator 自动生成的类型配置。 |
| `app/HotPot/.gitignore` | 排除 `library`、`temp`、`build`、`profiles`、`node_modules` 等可再生成目录。 |
| `app/HotPot/README.md` | 运行方法、核心代码位置、食材资源映射和 V0.1 功能摘要。 |

## 3. 主场景与核心代码

| 路径 | 作用 |
| --- | --- |
| `assets/scene/main.scene` | 游戏启动场景，包含 `Canvas`、2D 相机和 `HotPotGame` 组件。 |
| `assets/scene/main.scene.meta` | 主场景的 Creator UUID 和导入信息。 |
| `assets/scripts/core/HotPotGame.ts` | 游戏主控制器：创建界面、加载食材图片、绘制卡片、处理点击、托盘排序、三个消除、胜负、关卡切换和动画。 |
| `assets/scripts/core/HotPotGame.ts.meta` | 主控制器脚本 UUID；场景通过这个 UUID 绑定组件，不应随意删除或重建。 |
| `assets/scripts/data/GameData.ts` | 食材类型、中文名与配色、10 个关卡配置、随机牌堆、层级坐标和遮挡关系生成。 |
| `assets/scripts/data/GameData.ts.meta` | 数据脚本的 Creator UUID 和导入信息。 |
| `assets/scripts.meta`、`assets/scripts/core.meta`、`assets/scripts/data.meta` | 对应脚本目录的 Creator 元数据。 |
| `assets/scene.meta` | `scene` 目录的 Creator 元数据。 |

## 4. 食材图片资源

所有正式食材图片放在 `assets/resources/ingredients/`。运行时通过固定路径 `ingredients/<文件名>/texture` 加载，因此必须保留下面的英文文件名。

| 文件 | 游戏资源 | 运行时标识 |
| --- | --- | --- |
| `beef.png` | 牛肉 | `beef` |
| `shrimp.png` | 鲜虾 | `shrimp` |
| `vegetable.png` | 青菜 | `vegetable` |
| `mushroom.png` | 蘑菇 | `mushroom` |
| `corn.png` | 玉米 | `corn` |
| `fish.png` | 鱼片 | `fish` |

每张图片旁边的同名 `.meta` 文件保存 Creator 的 UUID、纹理过滤和透明通道设置。替换图片时应直接覆盖 PNG 文件，保留原文件名和 `.meta` 文件，然后在 Creator 中重新导入资源。

| 目录元数据 | 作用 |
| --- | --- |
| `assets/resources.meta` | 声明 `resources` 为 Creator 资源目录。 |
| `assets/resources/ingredients.meta` | 声明食材图片目录并保存目录 UUID。 |

## 5. 工具脚本

| 路径 | 作用 |
| --- | --- |
| `tools/validate-levels.cjs` | 在命令行验证 10 个关卡的数量、三消分组和预设可解路径。修改关卡数据后应运行它。 |
| `tools/create-placeholder-images.ps1` | 早期用于生成 JPG 文字占位图的辅助脚本；当前工程已使用正式 PNG，不应在现有资源目录上运行此脚本。 |

## 6. 工程设置

| 路径 | 作用 |
| --- | --- |
| `settings/v2/packages/project.json` | 项目通用设置，包含 `720 × 1280` 竖屏设计分辨率。 |
| `settings/v2/packages/scene.json` | 记录 Creator 当前打开的场景 UUID。 |
| `settings/v2/packages/builder.json` | 构建和纹理压缩设置，目前关闭自动生成 Mipmap。 |
| `settings/v2/packages/engine.json` | 引擎模块配置版本。 |
| `settings/v2/packages/device.json` | 设备预览配置版本。 |
| `settings/v2/packages/program.json` | Creator 程序级工程配置版本。 |
| `settings/v2/packages/information.json` | Cocos 启动画面服务相关配置。 |
| `settings/v2/packages/cocos-service.json` | Cocos 在线服务占位配置；V0.1 未接入在线服务。 |

## 7. Creator 自动生成目录

| 目录 | 作用 |
| --- | --- |
| `library/` | Creator 导入资源后的缓存，包括纹理和序列化资产。不要作为源文件修改。 |
| `temp/` | TypeScript 编译、预览脚本和编辑器临时文件。出现旧预览缓存时可关闭 Creator 后重建。 |
| `profiles/` | 本机编辑器偏好和工程会话信息。 |
| `build/` | 执行构建后生成的发布文件，当前可能尚未创建。 |

这些目录都可以由 Creator 重新生成，不应把业务修改直接写入其中。

## 8. 原 Hello World 模板资源

以下文件来自最初的 Cocos 3D Hello World 模板，当前 `main.scene` 没有引用它们，因此不会参与游戏逻辑：

| 路径或文件组 | 原用途 |
| --- | --- |
| `assets/model/helloWorld/*.FBX` | 岛屿、天空、士兵等 3D 模型。 |
| `assets/model/helloWorld/*.prefab` | 由模板模型组成的预制体。 |
| `assets/model/helloWorld/*.png`、`*.jpg` | 模板模型使用的贴图。 |
| `assets/model/helloWorld/grass/*` | 草模型、材质、贴图和预制体。 |
| `assets/material/*.mtl` | 模板 3D 模型的材质描述文件。 |
| `assets/skybox/sunnySkyBox.jpg` | 模板天空盒图片。 |
| 上述文件旁的 `.meta` | 对应资源和目录的 Creator UUID、导入器与依赖信息。 |

这些模板资源目前可以保留，便于追溯原工程；若以后要清理，应先确认场景和预制体没有引用，再通过 Creator 资源面板删除。

## 9. 常见修改入口

| 想修改的内容 | 应修改的文件 |
| --- | --- |
| 更换食材图片 | 覆盖 `assets/resources/ingredients/` 下的同名 PNG，保留 `.meta`。 |
| 调整牌面尺寸、图片边距、托盘布局 | `assets/scripts/core/HotPotGame.ts`。 |
| 修改关卡数量、食材种类或层数 | `assets/scripts/data/GameData.ts`。 |
| 修改设计分辨率 | `settings/v2/packages/project.json`，并同步检查主控制器中的设计尺寸常量。 |
| 修改场景入口或组件绑定 | `assets/scene/main.scene`，建议在 Creator 编辑器中操作。 |
