# 锅里捞啥 项目架构与目录索引

本文面向接手开发、排查问题和构建微信小游戏的成员。项目是 Cocos Creator 3.8.8 的 TypeScript 竖屏叠层三消游戏；Cocos 项目根目录是 `app/HotPot`。本文按当前工作区源码整理，历史交接文档可能描述旧版规则或旧资源。

## 一 项目架构

游戏场景 `assets/scene/main.scene` 挂载 `HotPotGame` 组件。场景代码按继承层分工，运行时仍只有一个游戏组件：

```text
HotPotGame  地区选择、存档冲突与结算弹窗
    ↑ HotPotDialogs  调试入口与食材详情
    ↑ HotPotPlayerMenus  图鉴与成就菜单
    ↑ HotPotProfileMenus  玩家档案与云存档选择
    ↑ HotPotTools  翻锅动画与胜负结算
    ↑ HotPotToolActions  道具、进度与奖励
    ↑ HotPotBoard  三消动画、托盘与寄存区
    ↑ HotPotBoardActions  关卡加载、棋盘与取牌
    ↑ HotPotView   主界面、标题、背景和装饰
    ↑ HotPotResources  音频与食材图片加载
    ↑ HotPotState  生命周期、存档恢复与玩家初始化
    ↑ HotPotFields  场景状态字段与界面引用
    ↑ Cocos Component

HotPotUi                 共用界面尺寸、颜色和绘制函数
GameConfig               食材、关卡与棋盘数据结构
GameData                 关卡生成、遮挡和炸牌选择
PlayerTypes              存档结构和初始玩家状态
RegionData               地区树校验与地区路径
PlayerData               存档校验、迁移和永久进度
CollectionData           图鉴文案与成就计算
PlayerServiceBase        本机档案状态与公开操作
PlayerService            云函数调用、云存储读取与冲突处理
CloudConfig              云环境、函数及集合名称
hotpotPlayerDev           微信云函数，处理 load、save、regions
```

`HotPotGame` 是场景挂载的唯一组件；其余 `HotPot*` 类通过继承为它提供方法。`HotPotUi.ts` 是界面工具模块，不在继承链内。`PlayerServiceBase` 定义存档状态和公开操作，`PlayerService` 实现微信云端与本机存储；数据模块不依赖场景节点。

基本数据流：点击食材后，`HotPotBoardActions` 处理取牌和相邻三消，`HotPotBoard` 绘制托盘及动画；`HotPotState.checkpointGame` 将当前对局交给 `PlayerServiceBase.setSave`。服务通过 `PlayerService.persist` 写本机缓存，再由 `PlayerService.request` 调用 `hotpotPlayerDev` 的 `load` 或 `save` 操作。云函数从微信本次调用上下文识别玩家，在 `hotpot_players_dev` 集合中通过事务读写档案，并用 `revision` 和 `mutationId` 处理并发及重试。地区树先从随包的 `assets/resources/data/regions.json` 加载；配置 `regionsFileId` 时，客户端才尝试云存储下载，失败后再调用云函数的 `regions` 操作。当前 `regionsFileId` 为空，正常路径使用随包地区文件。

云函数入口为 `cloudfunctions/hotpotPlayerDev/index.js`。`request-context.js` 取得调用身份，`handler.js` 校验请求并处理 `load`、`save`、`regions`；`PlayerTypes.js`、`RegionData.js`、`GameConfig.js`、`GameData.js`、`PlayerData.js` 是服务端数据模型与校验逻辑，和客户端同名 TypeScript 模块保持业务规则一致。`settings.json` 指定环境和集合，`regions.json` 提供随函数打包的地区数据。

## 四 开发和构建入口

用 Cocos Creator 3.8.8 打开 `app/HotPot`，在 `assets/scene/main.scene` 预览。业务源码采用 UTF-8、两个空格缩进、分号结尾；项目编辑器设置见 `app/HotPot/.editorconfig`。手动修改资源时保留对应的 `.meta` 文件，新增 TypeScript 资源后让 Creator 导入并确认元数据。

当前云开发构建由 `tools/build-cloud-dev.ps1` 和 `extensions/hotpot-cloud-build` 约束，输出目标是 `build/wechatgame-cloud-dev`。构建、上传代码、微信审核和正式发布是不同步骤。云函数源码改动后，需要重新准备并部署 `hotpotPlayerDev`；`exports/cloudbase-player-dev/hotpotPlayerDev.zip` 是导出时的副本，不会自动跟随源码更新。

本地回归入口位于 `app/HotPot/tools/`。重点运行 `validate-levels.cjs`、`validate-tray-animation.cjs`、`validate-player-save.cjs`、`validate-collection-ui.cjs` 与 `validate-cloud-gui.cjs`。实际设备上的资源显示和云端部署仍需在 Creator 与微信开发者工具中验证。
