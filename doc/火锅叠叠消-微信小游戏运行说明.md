# 火锅叠叠消：微信小游戏运行说明

当前工程已按 **Cocos Creator 3.8.8 + TypeScript** 的微信小游戏平台配置：竖屏、主场景 `main.scene`、调试构建，不启用开放数据域、引擎分离或 WASM 分包。

## 一键构建并打开

构建前先保存并关闭 Cocos Creator。Creator 3.8.8 在本机以单实例运行，编辑器未关闭时，另一个命令行构建进程可能一直等待。

在 PowerShell 中运行：

```powershell
cd D:\codeX\create\app\HotPot
powershell -ExecutionPolicy Bypass -File .\tools\build-wechat.ps1 -Open
```

脚本会执行以下操作：

1. 使用 Cocos Creator 3.8.8 构建 `wechatgame` 平台。
2. 将结果写入 `app/HotPot/build/wechatgame/`。
3. 检查 `game.json` 和 `project.config.json` 是否已生成。
4. 调用微信开发者工具。服务端口已开启时自动打开构建目录；服务端口关闭时打开入口页并提示导入路径。

## 使用自己的微信小游戏 AppId

脚本默认使用 Cocos 的测试 AppId `wx6ac3f5090a6b99c5`，足够在开发者工具中本地查看。真机预览、上传和发布时，应改为微信公众平台中小游戏项目自己的 AppId：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-wechat.ps1 `
  -AppId 'wx你的小游戏AppId' `
  -Open
```

不要把 AppSecret 写进工程或脚本。小游戏构建和开发者工具导入只需要 AppId。

## 只打开已有构建

如果已经成功构建过，只想重新打开微信开发者工具：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-wechat.ps1 -SkipBuild -Open
```

也可以直接在微信开发者工具中选择“导入项目”，目录填写：

```text
D:\codeX\create\app\HotPot\build\wechatgame
```

应导入构建目录，而不是 `app/HotPot` 的 Cocos 源工程目录。

微信开发者工具默认可能关闭“服务端口”。这是工具的安全设置，脚本不会擅自修改。关闭时，在已经打开的入口页点击“导入项目”，选择上述目录即可；如果你自行在“设置 → 安全设置”中开启服务端口，以后 `-Open` 就能自动载入项目。

## 修改代码或图片后的流程

覆盖 `assets/resources/ingredients/` 中的同名 PNG，或修改 TypeScript 后，需要重新执行构建脚本。微信开发者工具不会直接编译 Cocos 源工程。

目前六张食材原图尺寸较大。它们可以用于本机调试，但若正式上传时遇到主包体积限制，应先按实际显示尺寸缩小图片，再考虑 Cocos 的远程资源或微信小游戏分包。

## 常见问题

### 构建脚本提示 Creator 正在运行

保存工程，关闭所有 Cocos Creator 窗口，再运行脚本。脚本不会自动强制关闭编辑器，避免丢失未保存的场景修改。

### 开发者工具提示 AppId 不属于当前账号

本地查看可以继续使用测试 AppId；真机预览或上传需要传入当前微信账号有权限的小游戏 AppId。

### 修改图片后开发者工具仍显示旧图

先重新运行构建脚本，再在微信开发者工具中选择“工具 → 清除缓存 → 全部清除”，然后重新编译。
