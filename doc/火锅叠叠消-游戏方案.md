> 版本：V0.1

> 目标平台：微信小游戏  
> 后续平台：Android / HarmonyOS  
> 推荐引擎：Cocos Creator 3.x  
> 推荐语言：TypeScript

# 1. 游戏概述

## 1.1 游戏名称

暂定：

**《火锅叠叠消》**

备选名称：

- 火锅消不停
- 火锅叠叠乐
- 今晚吃火锅
- 火锅三三消
- 火锅食材大作战
- 吃货消消锅

---

# 2. 游戏定位

《火锅叠叠消》是一款基于：

**叠层牌 + 点击选择 + 三个相同食材消除 + 有限槽位管理**

的休闲小游戏。

玩家需要从层层堆叠的火锅食材中选择当前可以拿取的食材，并放入下方托盘。

当托盘中出现三个相同食材时，对应食材自动消除。

玩家需要在托盘被塞满之前，不断消除食材，并最终完成本关的火锅订单或清空全部食材。

游戏设计目标：

- 规则简单，10 秒学会。
- 操作简单，只需要点击。
- 前期轻松，后期具有明显的槽位压力。
- 玩家经常产生“只差一个就能消掉”的心理。
- 单局失败后可以立即重新开始。

核心体验不是传统交换式消消乐，而是：

> **“我下一张到底应该拿什么？”**

# 3. 核心玩法

## 3.1 基础牌面

游戏区域中存在大量食材牌。

例如：

- 🥩 牛肉
- 🍤 虾
- 🥬 青菜
- 🍄 蘑菇
- 🌽 玉米
- 🐟 鱼片

食材牌会以多层堆叠的方式摆放。

示意：

```text
             🥩

        🍤        🥬

     🍄     🥩      🍤

  🥬    🐟    🌽    🥩
```

部分食材会覆盖在其他食材之上。

---

# 4. 食材可点击规则

只有当前没有被其他牌覆盖的食材才能点击。

例如：

```text
       🥩
   🍤      🥬
```

如果 🥩 压住下面两张牌的一部分，则 🍤、🥬 暂时不可选择。

玩家先移除 🥩，下面两张牌才会解锁。

因此游戏具有一个非常重要的体验：

> 玩家能够看到下面存在什么食材，但暂时拿不到。

这样会产生：

> “只要把上面这个清掉，下面那张牛肉就出来了。”

这也是游戏最重要的上头机制之一。

---

# 5. 托盘系统

屏幕底部设置一个托盘。

默认：

**7 个槽位。**

例如：

```text
┌──────────────────────────┐
│ 🥩 │ 🍤 │ 🥩 │ 🥬 │   │   │   │
└──────────────────────────┘
```

玩家点击食材后，食材进入托盘。

例如点击：

```text
🥩
```

托盘变成：

```text
┌──────────────────────────┐
│ 🥩 │ 🍤 │ 🥩 │ 🥬 │ 🥩 │   │   │
└──────────────────────────┘
```

---

# 6. 三消规则

当托盘中出现三个相同食材：

```text
🥩 🥩 🥩
```

立即自动消除。

例如：

```text
消除前：

[🥩][🍤][🥩][🥬][🥩][🍄]

消除后：

[🍤][🥬][🍄][ ][ ][ ][ ]
```

玩家不需要手动拖动或者交换食材。

整个操作只有：

**点击。**

---

# 7. 胜负条件

## 7.1 胜利

基础版本推荐支持两种关卡目标。

### 类型 A：清空地图

玩家将所有食材消除：

```text
剩余食材：0
```

即可过关。

### 类型 B：完成火锅订单

例如当前订单：

```text
🥩 牛肉   0 / 9
🍤 虾     0 / 6
🥬 青菜   0 / 6
```

每成功消除三个对应食材：

```text
🥩 ×3
```

订单增加：

```text
🥩 牛肉   3 / 9
```

当全部订单完成：

```text
🥩 9 / 9
🍤 6 / 6
🥬 6 / 6
```

立即过关。

推荐：

**前期以清空地图为主。**

中后期逐渐加入订单模式。

## 7.2 失败

托盘共有 7 格。

如果 7 格全部放满，并且没有发生三消：

```text
[🥩][🍤][🥬][🍄][🌽][🐟][🦀]
```

游戏失败。

显示：

```text
托盘满啦！

还差一点就成功了！

[再试一次]

[使用道具继续]
```

# 8. 核心游戏循环

完整流程：

```text
进入关卡
   ↓
观察食材布局
   ↓
选择一张可点击食材
   ↓
食材进入托盘
   ↓
是否存在3个相同食材？
   ↓
是
   ↓
自动消除
   ↓
刷新牌面可点击状态
   ↓
继续选择
```

失败循环：

```text
托盘塞满
   ↓
失败
   ↓
重新挑战
```

整个游戏应该尽可能减少多余操作。

---

# 9. 游戏的“上头点”

本游戏需要重点围绕以下几个心理设计。

## 9.1 看得见，但拿不到

玩家能看到下层有：

```text
🥩
```

但它被：

```text
🍄
```

盖住。

玩家会自然形成目标：

> 我要把蘑菇清掉，把牛肉拿出来。

## 9.2 永远差一个

典型托盘：

```text
🥩 🥩
🍤 🍤
🥬
```

此时玩家最期待：

```text
再来一个 🥩
```

或者：

```text
再来一个 🍤
```

这种“差一个”的状态应该在关卡设计中频繁出现。

## 9.3 槽位压力

例如：

```text
[🥩][🥩][🍤][🍤][🥬][🍄][ ]
```

只剩 1 格。

此时玩家会产生明显紧张感。

如果下一张找到牛肉：

```text
🥩
```

立即：

```text
🥩🥩🥩
```

消除。

托盘突然从 7 格快满变成 4 格。

这种瞬间释放，是游戏最重要的爽点之一。

# 10. 食材设计

V0.1 推荐只使用 6 种食材。

| ID | 食材 |
|---|---|
| beef | 🥩 牛肉 |
| shrimp | 🍤 虾 |
| vegetable | 🥬 青菜 |
| mushroom | 🍄 蘑菇 |
| corn | 🌽 玉米 |
| fish | 🐟 鱼片 |

不要一开始放十几种。

食材种类越多，托盘压力越大。

因此食材数量也是最简单的难度控制手段。

---

# 11. 火锅主题特殊机制

为了避免游戏变成单纯的“羊了个羊换皮”，加入少量火锅特色机制。

第一版只推荐一个：

## 火锅牌

牌堆中偶尔存在：

```text
🍲
```

火锅牌本身不能直接点击。

必须先将覆盖它的食材全部移除。

例如：

```text
     🥩
  🍤   🥬

     🍲
```

清掉上面的食材后，火锅自动激活。

---

# 12. 火锅奖励

火锅激活之后触发一个奖励。

V0.1 推荐：

**自动移除托盘中数量最少的一种食材。**

例如当前：

```text
[🥩][🥩][🍤][🥬][🥬][🍄]
```

数量：

```text
🥩 ×2
🥬 ×2
🍤 ×1
🍄 ×1
```

系统随机选择 🍤 或 🍄，移除一个。

立即释放槽位。

玩家因此会产生新的目标：

> 先挖到火锅。

相当于牌堆里存在一个“小救命点”。

# 14. 道具

初期只需要三个。

## 14.1 撤回

撤销最近一次操作。

建议每局免费 1 次，之后可以通过广告获得。

## 14.2 移出

选择托盘中的 3 张牌，暂时放到旁边，给玩家一次翻盘机会。

## 14.3 洗牌

重新排列当前所有未被消除的牌。

牌的数量、种类不改变，只改变位置。

# 16. 关卡设计

建议前期采用渐进式难度。

## 第 1 关

```text
牌数：18
种类：3
层数：2
```

目的：纯教学。

成功率应该接近 100%。

## 第 2 关

```text
牌数：30
种类：4
层数：2
```

依然非常简单。

## 第 3～5 关

```text
牌数：45～60
种类：4
层数：3
```

让玩家理解需要考虑下面压住的牌。

## 第 6～10 关

```text
牌数：60～90
种类：5
层数：3～4
```

开始制造托盘只剩 1～2 格，然后再让玩家成功翻盘的场景。

## 第 11～20 关

```text
牌数：90～120
种类：6
层数：4～5
```

加入火锅牌。

建议：

**Q版、暖色、轻松、食欲感强。**

- 木桌
- 蒸汽
- 食材盘

# 25. 牌之间的遮挡关系

这是整个游戏最核心的数据结构。

例如：

```text
A牌
↓
覆盖
↓
B牌
```

可以记录：

```ts
A.covering = [B]
B.blockedBy = [A]
```

只有：

```ts
blockedBy.length === 0
```

时：

```ts
isSelectable = true
```

A 被移除后，从 B.blockedBy 中删除 A。

如果：

```ts
B.blockedBy.length === 0
```

则 B 解锁。

# 26. 托盘数据

例如：

```ts
[
  "beef",
  "shrimp",
  "beef",
  "vegetable",
  "beef"
]
```

每次加入新牌后检测同类型数量。

如果：

```text
>= 3
```

则移除三个。

V0.1 建议：

**自动把同类型食材排列在一起。**

例如：

```text

🥩 🍤 🥬 🥩
```

加入：

```text
🥩
```

自动整理：

```text
🥩 🥩 🥩 🍤 🥬
```

然后三张牛肉消除。

这种交互更加直观。

# 33. MVP成功判断标准

找 5～10 个人试玩。

观察以下几个指标。

## 指标一

玩家是否能够：

```text
10秒内理解规则
```

## 指标二

第一次失败之后是否主动：

```text
点击再来一次
```

而不是直接退出。

## 指标三

游戏过程中是否会说：

> “就差一个牛肉！”

或者：

> “下面那个虾怎么拿出来？”

如果玩家出现这种行为，说明核心机制开始有效。

# 34. 最关键的设计原则

整个游戏开发过程中始终遵循：

```text
简单规则
+
有限槽位
+
信息部分可见
+
差一个就消除
+
经常出现死里逃生
```

不要通过：

- 大量系统
- 复杂数值
- 大量按钮
- 复杂剧情

制造游戏性。

真正需要打磨的是：

- 牌怎么叠。
- 什么牌先露出来。
- 什么时候让玩家只剩一个槽位。
- 什么时候又突然给玩家一个可以三消的机会。

最终目标不是让玩家认为：

> “这个游戏很复杂。”

而是让玩家产生：

> “这把我肯定能过。”

然后：

> “就差一点。”

最后：

> **“再来一把。”**
