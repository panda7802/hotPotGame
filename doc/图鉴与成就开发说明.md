# 图鉴与成就

日期：2026-10-20。分支：`codex/cloudbase-player-save`。

## 玩家入口与玩法

关卡信息条左侧新增「图鉴」，右侧仍是「档案」。点击图鉴进入「小馆珍藏」，包含两个标签：

- **食材图鉴**：现有13种食材，首次在游戏里拿取并稳定结算后点亮；未发现项显示问号。点开卡片查看食材小档案。重开、撤回不熄灭已发现项。
- **我的成就**：14项成就，显示进度条与达成状态；列表上下滑动，无分页。新成就在正常游戏中提示，通关时也显示本次新达成的成就。

| 成就 | 条件 |
| --- | --- |
| 开锅尝鲜 | 发现第一种食材 |
| 初次开席 | 单局消除至少3份食材 |
| 家乡有味 | 为小馆选择一次地区 |
| 五味俱全 / 十全食客 / 满汉小馆 | 发现5 / 10 / 13种食材 |
| 热锅熟手 / 百味入锅 / 火候大师 | 单局消除至少30 / 100 / 300份食材 |
| 第一锅香 / 热锅行家 / 千层掌勺 | 分别通关第1 / 2 / 3关 |
| 一气呵成 | 任意一关不使用复活通关 |
| 三锅圆满 | 完成全部3关 |

消除数量是棋盘移除数量减去托盘与寄存区数量，包含正常三消和炸道具消除。不把重复重开或撤回后的重复操作累加为累计数量。当前成就是纪念徽章，不额外发放道具或改变关卡难度。

## 图片与包体

本版没有新增图片。图鉴直接复用游戏已加载的手绘食材 SpriteFrame；未解锁问号、成就卡片、徽章状态和进度条使用文字/Graphics 绘制。因此无需为这次功能新增云存储资源或图片下载。

以后新增大量专属高清插画时，可将高清详情图放云存储或 CDN，仅在打开详情时加载，并保留本地缩略图和失败占位；本版没有启用这条远程加载链路。现有构建流程仍检查4 MB包体限制，新版实际体积需重新构建后确认。

## 存档结构与兼容

在原 `hotpot_players_dev` 文档的 `state` 内新增 `progress`，不需要新建集合或修改权限：

```json
{
  "version": 1,
  "discovered": ["beef", "shrimp"],
  "bestCleared": [0, 0, 0],
  "completedLevels": [],
  "cleanWins": [],
  "regionChosen": false
}
```

- `discovered`：已拿取过的食材集合，按照食材配置顺序保存。
- `bestCleared`：各关的单局最高消除数，固定3项，取最大值，不累加。
- `completedLevels` / `cleanWins`：通关、无复活通关的关卡索引集合（0代表第1关）。
- `regionChosen`：是否曾选择地区；之后清空地区也保留已达成成就。

成就状态根据这些永久记录计算，不另外维护容易失去一致性的成就 ID 列表。所有字段与棋盘、地区一起使用现有本机缓存、自动同步、事务版本号和重试去重机制。

旧存档缺少 `progress` 时自动补默认值，并根据当前保存的一局补认已经拿取的食材、消除数、通关状态和已有地区。旧版本没有记录的历史对局无法全部追溯。历史永久记录不会因为重开当前对局被清空。

冲突时，棋盘和地区仍由玩家选择版本；图鉴和通关集合取并集、各关最高消除数取最大值。云函数也进行同样的单调合并，仍在运行的旧客户端即使不提交 `progress`，也不会清空已保存的永久记录。不同微信账号仍隔离，游客图鉴不自动合并到登录账号；选择“将当前这锅保存到账号”只导入该局可确认的记录。

## 必须先更新云函数

**部署顺序：先更新 `hotpotPlayerDev`，再构建新小游戏。**

新云函数的 `load` / `save` 响应带 `progressVersion: 1`。新客户端首次连接会检查这一能力；如果仍是旧函数，将显示“请先更新云函数再同步图鉴与成就”，保留本机记录，避免静默丢弃新增字段。不要用旧导出包回退这个函数。

本地源码已准备好，函数仍使用环境 `cloud1-d2gc9q7cobffff893` 和原 ADMINONLY 集合。没有登录云控制台、远程部署、改权限或发布小游戏。

你可以按照 [后台操作指南](CloudBase后台手动操作指南.md) 部署开发函数，再按照 [Cocos 图形界面构建指南](Cocos图形界面构建云开发版.md) 重新构建。GUI 构建扩展只更新本地函数文件，不会自动部署云端。

若手动上传云函数，使用更新的 `exports/cloudbase-player-dev/hotpotPlayerDev.zip`，根目录包含 `handler.js`、`PlayerData.js` 等文件，并远程安装锁定依赖。

后台重置当前对局时，只修改 `state.save`，保留 `state.progress`。手工修改永久记录需要遵循字段校验、版本号递增与关闭玩家客户端的流程；正常游戏保存会保留历史最高值，不提供游戏内清空永久记录按钮。

- `assets/scripts/data/CollectionData.ts`：食材故事、14项成就名称和目标。
- `assets/scripts/data/PlayerData.ts`：永久记录校验、旧存档迁移、稳定存档提取和合并。
- `assets/scripts/core/PlayerService.ts`：同步、冲突合并和云函数能力检查。
- `assets/scripts/core/HotPotGame.ts`：入口、滑动列表、食材详情及达成提示。
- `cloudfunctions/hotpotPlayerDev/handler.js`：云端兼容、能力标记和永久记录合并。

本地测试覆盖936张牌的完整三关稳定存档、13种食材收集、14项成就、旧存档迁移、重复恢复/重开/撤回、坏数据、不同账号隔离、跨设备模拟、旧客户端保存、冲突合并和旧云函数拒绝。

遵照“只写代码”的要求，没有启动 Cocos 构建或操作模拟器。界面滑动、手机展示和真实云端联调仍待你重新构建/部署后验收。
