# 本工程的云函数：编写、发布与调用

更新时间：2026-10-27。本文按当前工作区源码编写，适用于 Cocos Creator 3.8.8 的微信小游戏工程 `app/HotPot`。

本文中的新函数 `hotpotHelloDev` 是教学示例，尚未在工程中创建或上传。以下命令供你学习后手动执行；本文编写过程中没有发布云函数或小游戏，也没有查询云端当前版本。

## 1. 先理解整条链路

```text
Cocos 游戏中的 TypeScript 代码（玩家设备）
  → wx.cloud.init 选择云环境
  → wx.cloud.callFunction 指定函数名并发送 data
  → 云端执行该函数的 index.js / exports.main(event, context)
  → 校验身份和参数，执行业务，按需访问数据库
  → return 返回 JSON 数据
  → 客户端从 response.result 取结果，更新界面
```

云函数是运行在微信云开发环境中的后端程序。你在电脑上编写源文件，发布后才会改变云端执行的代码。游戏通过函数名调用，不需要自己搭建 HTTP 服务器。

这里要区分三个动作：

| 动作 | 本工程对应内容 | 会改变云端吗 |
| --- | --- | --- |
| 准备云函数文件 | `prepare-cloud.cjs` 生成共享 JS、配置、地区数据 | 不会 |
| 发布云函数 | 开发者工具上传，或 `deploy-cloud-dev.ps1` | 会更新目标云函数 |
| 构建和发布小游戏 | Cocos 构建，再由微信开发者工具上传小游戏 | 构建只生成本地包，上传/发布是后续操作 |

只改云函数内部实现，且请求和响应兼容时，通常只需重新部署云函数。新增按钮、修改客户端调用或修改共享协议，还需要重新构建客户端；玩家使用新版客户端则需走小游戏相应的上传和发布流程。

### 为什么工程下没有 tcb，也能运行

`tcb` 是 `@cloudbase/cli` 提供的命令。`npm i -g @cloudbase/cli` 安装到当前 npm 的全局目录，不会把它加入工程的 `node_modules`。

本工程现有发布脚本使用微信开发者工具安装目录中的 **`cli.bat`**，没有调用 `tcb`，所以无需先全局安装 CloudBase CLI。

几个容易混淆的依赖分别是：

| 名称 | 用途 |
| --- | --- |
| `@cloudbase/cli` / `tcb` | 本机命令行管理工具；当前发布脚本没有使用 |
| 微信开发者工具 `cli.bat` | 当前脚本实际使用的上传工具 |
| `wx.cloud` | 微信小游戏运行时提供的客户端 API；当前玩家服务用它调用云函数 |
| `wx-server-sdk` | 云函数内使用的服务端 SDK；本函数用它访问数据库等资源 |
| `@cloudbase/node-sdk` | 本函数用它解析平台传入的本次调用上下文 |

仓库根目录 `package.json` 中的 `@cloudbase/js-sdk` 等依赖，与云函数自己的依赖分开。云函数依赖写在该函数目录的 `package.json`，不能因为根目录安装过某个包就假定云端也能使用。

### 3.1 入口：把平台调用交给业务代码

入口导出形式是：

```javascript
exports.main = async (event, context) => {
  // event：客户端 data 中的业务参数。
  // context：平台传入的本次调用上下文。
  return {ok: true};
};
```

当前 `index.js` 初始化服务端 SDK，加载配置、共享逻辑和地区数据，通过 `requestIdentity()` 从本次 `context` 解析微信身份，再交给 `createHandler()`。

这个工程刻意不信任客户端传来的 `openid`、`playerId` 或环境字段，也不从进程中可能残留的微信身份读取当前玩家。修改身份相关代码时保留这一边界，具体实现见 [request-context.js](../app/HotPot/cloudfunctions/hotpotPlayerDev/request-context.js)。

### 3.2 一个云函数用 action 区分业务

`hotpotPlayerDev` 是一个已部署的函数，里面有三个业务操作：

| `event.action` | 作用 | 主要结果 |
| --- | --- | --- |
| `load` | 加载当前玩家；首次调用会创建初始档案 | `player`、协议版本 |
| `save` | 校验并保存当前玩家状态 | 最新 `player`，或 `conflict: true` |
| `regions` | 返回校验后的地区树 | `regions` |

因此，“增加一个业务操作”和“新建一个云函数”不同。前者是在现有 `handler.js` 中扩展 action 和对应校验；后者要新增独立目录、依赖与部署目标。

### 3.3 玩家身份和数据库

当前玩家文档 ID 是 `SHA256(APPID + ':' + OPENID)` 的前 32 位。同一微信身份据此定位自己的文档，原始 OpenID 不返回客户端。

`handler.js` 在服务端访问 `hotpot_players_dev`，保存 `state`、`revision`、`lastMutationId` 等字段。集合使用仅管理员可读写权限，客户端经云函数访问。源码中的规则参考文件不会自动应用到云端，实际权限需在云开发控制台核对。

`save` 除了状态数据，还要求：

- `expectedRevision`：客户端所基于的云端版本；版本不一致时返回冲突。
- `mutationId`：本次修改编号；最近一次相同编号的重试会返回已有结果。
- `state`：完整玩家状态，服务端通过共享逻辑校验。

这些逻辑在数据库事务中执行，避免两台设备无条件互相覆盖。不要把教学用的简单写入逻辑直接替换到现有存档流程。

## 4. 修改并发布现有 hotpotPlayerDev

### 4.1 修改正确的源文件

- 改云端业务：编辑 `handler.js`，必要时修改 `index.js`。
- 改身份解析：编辑 `request-context.js`。
- 改存档校验、类型、游戏共享逻辑：编辑 `assets/scripts/data/` 下对应 `.ts` 文件。
- 改环境配置：编辑 `CloudConfig.ts`。
- 增减服务端 npm 包：在 `cloudfunctions/hotpotPlayerDev` 目录管理依赖和锁文件。

不要只手动修改生成的 `PlayerData.js` 或 `settings.json`：下次运行准备脚本会覆盖它们。

### 4.2 准备与检查

以下命令从仓库根目录 `D:\codeX\create` 执行。Creator 路径按你电脑实际安装位置修改，不能把不同电脑的安装路径照抄。

## 5. 客户端如何调用现有函数

当前实际封装在 `PlayerService.ts`：连接时 `cloud.init`，随后 `request()` 调用函数。下面是等价的简化示例，可在微信开发者工具的**小游戏运行上下文 Console** 中学习：

```javascript
wx.cloud.init({env: 'cloud1-d2gc9q7cobffff893'});

wx.cloud.callFunction({
  name: 'hotpotPlayerDev',
  config: {env: 'cloud1-d2gc9q7cobffff893'},
  data: {action: 'load'},
  success(response) {
    const result = response.result;
    if (!result || !result.ok) {
      console.error('业务失败', result && result.code);
      return;
    }
    console.log('玩家编号', result.player.playerId);
    console.log('存档版本', result.player.revision);
  },
  fail(error) {
    console.error('调用失败', error);
  },
});
```

`data` 会成为云端 `event`，云端 `return` 会成为客户端 `response.result`。进入 `success` 仍需判断业务字段 `ok`；例如 `{ok: false, code: 'IDENTITY_REQUIRED'}` 是函数已执行、业务未通过。

注意 `load` 首次调用可能创建玩家档案。不要在普通浏览器或 Node 终端直接运行这段代码，那些地方没有微信小游戏运行时的 `wx.cloud`。

现有 `PlayerService.request()` 还检查图鉴和对局协议。当前源码的 `PROGRESS_VERSION = 1`、`PLAY_SESSION_VERSION = 4`，定义于 `PlayerTypes.ts`。这描述的是本地源码要求，不能证明云端已部署到此版本。协议变化时应先更新云函数，再构建客户端。

游戏通常先写本地存档，约 1.5 秒合并一次云同步；手写调用示例只用于理解接口，正式存档操作继续走 `PlayerService`，以保留重试、冲突和离线处理。

## 6. 从零新建一个云函数：hotpotHelloDev

先做一个不访问数据库、不依赖微信身份的问候函数，跑通“编写 → 部署 → 调用”。完成后再加入数据库和身份校验。

### 6.1 创建目录和两个文件

在 `app/HotPot/cloudfunctions/` 下新建 `hotpotHelloDev` 文件夹。与现有玩家函数平级，不要放进 `assets`：

```text
cloudfunctions/
├─ hotpotPlayerDev/
└─ hotpotHelloDev/
   ├─ index.js
   └─ package.json
```

`index.js`：

```javascript
'use strict';

exports.main = async (event = {}) => {
  if (event.action !== 'hello') {
    return {ok: false, code: 'INVALID_ACTION'};
  }
  if (typeof event.name !== 'string') {
    return {ok: false, code: 'INVALID_NAME'};
  }
  const name = event.name.trim();
  if (!name || name.length > 20) {
    return {ok: false, code: 'INVALID_NAME'};
  }
  return {
    ok: true,
    message: `你好，${name}！`,
    serverTime: Date.now(),
  };
};
```

`package.json`：

```json
{
  "name": "hotpot-hello-dev",
  "version": "1.0.0",
  "private": true,
  "main": "index.js"
}
```

这个函数只使用 JavaScript 自带能力，因此无需安装 SDK。函数目录名、部署名称、调用时的 `name` 保持为 `hotpotHelloDev`；`package.json` 的 `name` 是 npm 包名，不是客户端查找云函数的依据。

### 6.2 先在本地检查

在仓库根目录运行：

```powershell
node -e "require('./app/HotPot/cloudfunctions/hotpotHelloDev/index.js').main({action:'hello',name:'小锅'}).then(console.log)"
```

应看到 `ok: true`、问候语和时间戳。该检查仅覆盖普通 JS 逻辑，不模拟微信身份、数据库或云端网络。

### 6.5 接入 Cocos 业务代码

把调用放进独立的服务或对应功能组件，用 `(globalThis as any).wx` 获取运行时对象，先判断 `wxHost?.cloud` 是否存在。在已有云初始化完成后调用新函数，并处理调用失败与业务失败。

不要把 `CloudConfig.ts` 中玩家服务的 `functionName` 改成 `hotpotHelloDev`，否则原存档请求也会发给新函数。给新服务单独定义函数名，环境 ID 可以复用 `CLOUD_CONFIG.environmentId`。

不要直接复用现有 `PlayerService.request()` 调问候函数：它固定使用玩家函数名，还要求玩家协议版本字段。为新业务单独封装调用即可。

接入后重新构建小游戏开发包，再从界面触发调用验收。界面构建流程见 [Cocos 图形界面构建云开发版](Cocos图形界面构建云开发版.md)。

## 7. 下一步：让新函数读写数据库

问候示例跑通后，可按现有玩家函数的结构扩展：

1. 在新函数目录添加服务端依赖。当前玩家函数锁定 `wx-server-sdk@3.0.1`、`@cloudbase/node-sdk@2.10.0`，可先按本工程已用版本学习；升级版本应另行核对兼容性。
2. 若需要登录身份，参考 `request-context.js`，解析本次平台上下文并校验 AppID、环境；不要接受客户端自行声明的身份。
3. 在开发环境创建新集合，例如 `hotpot_notes_dev`，核对云端权限，不要复用现有玩家存档集合练习。
4. 校验输入的类型、长度、业务范围；由服务端决定当前用户可读写哪些记录。
5. 用服务端 SDK 访问新集合。涉及计数、奖励、余额或并发写入时，设计事务和请求去重。
6. 只返回客户端需要的字段，错误响应采用稳定错误码；服务端诊断日志避免记录身份凭据和完整私有存档。
7. 从真实小游戏验证自己的数据，再用第二个账号验证隔离。云控制台测试通常没有真实小游戏调用身份，不能替代这一步。

现有项目对上下文的处理依据可查[CloudBase Node SDK 的官方实现](https://github.com/TencentCloudBase/node-sdk/blob/master/src/cloudbase.ts)；本工程实现和锁定依赖仍以实际源文件为准。

## 8. 常见问题对照

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `tcb` | 当前流程用微信 `cli.bat`，核对脚本中的工具路径 |
| 工具里看不到新函数目录 | 打开的是不是开发构建目录，`cloudfunctionRoot` 是否指向源码目录 |
| 云端找不到函数 | 调用名称是否与部署名称一致，是否上传到了同一个环境 |
| `Cannot find module` | 文件是否在函数上传目录内；依赖是否写入该函数的 `package.json` 并在云端安装 |
| 修改了共享 TS，云端仍是旧规则 | 是否重新执行准备脚本并重新部署；只构建客户端不会更新云函数 |
| `IDENTITY_REQUIRED` | 是否从真实小游戏调用，AppID 是否匹配，云环境关联及上下文是否正确 |
| `DEVELOPMENT_ENV_REQUIRED` | 配置、实际运行环境、集合名是否符合当前开发函数要求 |
| `DATABASE_UNAVAILABLE` | 查看云端日志、集合是否存在、数据库访问是否正常；响应没有暴露底层异常 |
| 调用进入 success 但功能失败 | 继续检查 `response.result.ok` 和 `code` |
| `CLOUD_UPGRADE_REQUIRED` / `DAILY_UPGRADE_REQUIRED` | 云函数协议版本与客户端不一致，先部署匹配的云端代码 |
| 普通浏览器中只显示本地保存 | 当前玩家服务依赖微信 `wx.cloud`，应在微信小游戏环境联调 |
| 集合权限不对 | 规则文件只是参考，要检查云控制台实际生效的权限 |

学习时可先完成第 6 节：本地返回问候语、云端部署成功、小游戏调用成功、非法参数得到预期错误码。再阅读现有玩家函数的身份、事务和存档协议，逐步增加自己的业务。
