# 火锅叠叠消：手动开发指南

本文面向需要直接修改工程代码的人。工程使用 **Cocos Creator 3.8.8 + TypeScript**，工程目录是 `app/HotPot`。

## 1. 修改前先知道这些

- 只修改 `app/HotPot/assets/`、`app/HotPot/settings/` 和 `app/HotPot/tools/` 中的源文件。
- 不要修改 `library/`、`temp/`、`build/`。它们是 Creator 自动生成的缓存或构建结果，下次导入、预览或构建时会被覆盖。
- 不要随意删除 `.meta` 文件。它们保存资源 UUID，删除后可能导致场景或资源引用丢失。
- 修改 TypeScript 后保存文件，Creator 通常会自动编译。修改图片或音频后，回到 Creator 等待资源导入完成再预览。
- 微信开发者工具看到的代码来自 `build/wechatgame*`，修改源代码后必须在 Creator 中重新构建，不能只点微信工具的“编译”。

## 2. 推荐的修改流程

1. 用 Cocos Creator 3.8.8 打开 `app/HotPot`。
2. 用 Creator 内置代码编辑入口或 VS Code 打开要修改的 `.ts` 文件。
3. 保存代码，回到 Creator 查看控制台是否有红色错误。
4. 打开 `assets/scene/main.scene`，点击顶部预览按钮验证。
5. 修改关卡后运行：

   ```powershell
   cd D:\codeX\create\app\HotPot
   node .\tools\validate-levels.cjs
   ```

6. 发布微信小游戏时重新执行 Creator 的“项目 → 构建发布”，平台选择“微信小游戏”，然后在微信开发者工具中重新编译。

## 3. 两个主要代码文件

### `assets/scripts/core/HotPotGame.ts`

负责界面与运行逻辑，包括：

- 创建标题、关卡栏、棋盘、托盘和按钮；
- 加载背景、食材和音频；
- 处理牌面点击、遮挡、托盘自动归并、三个消除、左移补位和胜负；
- 处理重新开始确认，以及第 3 关起的撤回、移出和洗牌道具；
- 适配不同纵横比和微信安全区域。

移动中的食物牌会在 `onTileClicked()` 中临时转移到 `FoodTransitionLayer`。这个容器在界面最后创建，因此牌从棋盘飞向 7 格托盘的过程中始终显示在边框之上。若以后增加新的全屏 UI，应继续让该容器位于普通游戏界面的最上层，结果弹窗除外。

托盘会自动整理同类食材。`insertIntoTray()` 把新牌插入已有同类食材之后，`findAdjacentMatch()` 检测归并后的三个同类食材。例如 `[牛肉, 牛肉, 虾]` 再加入牛肉时，会先成为 `[牛肉, 牛肉, 牛肉, 虾]`，然后三张牛肉播放消除动画，虾同时向左补位。`renderTray()` 将固定槽位和真实食材拆成两层；`animateMatch()` 直接移动 `TrayItem_*` 食材节点，不创建副本，因此不会保留旧图后再跳转。移动时长为 `0.62` 秒。暖色粒子由 `createTrayMatchBurst()` 创建，当前为 `12` 个。

文件顶部是最常改的尺寸参数：

```ts
const DESIGN_WIDTH = 720;       // 设计宽度
const DESIGN_HEIGHT = 1280;     // 设计高度
const TILE_WIDTH = 92;          // 棋盘牌宽
const TILE_HEIGHT = 76;         // 棋盘牌高
const TILE_IMAGE_WIDTH = 88;    // 棋盘食材图显示宽度
const TILE_IMAGE_HEIGHT = 68;   // 棋盘食材图显示高度
const TRAY_IMAGE_WIDTH = 78;    // 托盘食材图显示宽度
const TRAY_IMAGE_HEIGHT = 62;   // 托盘食材图显示高度
const IMAGE_CROP_X = 0.04;      // 图片左右裁掉的比例
const IMAGE_CROP_Y = 0.06;      // 图片上下裁掉的比例
```

常见界面位置位于 `buildShell()`。坐标以画布中心为原点，`x` 向右增加，`y` 向上增加。例如：

```ts
this.board.setPosition(0, 32 + this.topSpread);
```

第一个数字控制左右，第二个数字控制上下。这里的 `32` 越小，棋盘越向下；建议每次只调整 `5～10`。当前棋盘区域为 `680 × 670`，8 行关卡的牌面缩放为 `0.82`、纵向行距为 `78`，保证同一层的相邻行不重叠。`topSpread` 和 `bottomSpread` 是长屏安全区域适配量，手动调整位置时应保留，否则微信长屏设备可能重新出现黑边或遮挡。

背景由 `loadIllustratedBackdrop()` 加载，棋盘插画由 `loadBoardIllustration()` 加载。当前背景、棋盘插画和右下角火锅都是静态节点，没有雾气或循环动画。

### `assets/scripts/data/GameData.ts`

负责食材与关卡数据。`LEVELS` 中每一项是一关：

```ts
{level: 3, title: '小菜叠盘', typeCount: 5, typeOffset: 3, layers: [24, 24, 24], traySize: 7, rows: 8}
```

- `level`：显示的关卡编号；
- `title`：标题；
- `typeCount`：本关使用的食材种类数，范围为 1～10；
- `typeOffset`：从 13 种食材池的哪个位置开始轮换，用于让不同关卡出现不同组合；
- `layers`：每层牌数，从底层到顶层；
- `traySize`：托盘最大容量。
- `rows`：每层牌阵行数；第 3～10 关固定为 8 行。

每层牌数必须是 3 的倍数，否则不能保证按三个一组消除。修改完务必运行 `tools/validate-levels.cjs`。

第 3 关开始显示三种道具，每关各 1 次：

- `撤回`：恢复最近一次拿取前的棋盘和托盘；
- `移出`：从托盘末尾移出最多 3 张食材；
- `洗牌`：随机重排棋盘上尚未拿取的食材类型，遮挡结构不变。

道具出现关卡和次数在 `HotPotGame.ts` 的 `loadLevel()` 中设置。重新开始按钮调用 `showRestartConfirmation()`，只有在确认弹窗中再次点击“重新开始”才会清空本关进度。

牌的横纵间距在 `buildPositions()` 中：

```ts
const spacingX = targetRows ? (columns <= 3 ? 176 : 156) : (columns === 6 ? 96 : 108);
const spacingY = targetRows ? 78 : 90;
```

遮挡判定在 `createLevel()` 的末尾：横向距离小于 `78` 且纵向距离小于 `66` 时，上层牌会遮挡下层牌。改变牌面尺寸后，应同步检查这两个数值。

## 4. 手动更换图片

### 食材图片

目录：`assets/resources/ingredients/`

文件名固定为：

| 文件 | 食材 |
| --- | --- |
| `beef.png` | 牛肉 |
| `shrimp.png` | 鲜虾 |
| `vegetable.png` | 青菜 |
| `mushroom.png` | 蘑菇 |
| `corn.png` | 玉米 |
| `fish.png` | 鱼片 |
| `egg.png` | 鹌鹑蛋 |
| `jzg.png` | 金针菇 |
| `meetball.png` | 肉丸 |
| `ou.png` | 莲藕 |
| `tomato.png` | 番茄 |
| `toufu.png` | 豆腐 |
| `ydf.png` | 油豆腐 |

建议使用 `384 × 288`、透明背景的 PNG。直接覆盖同名图片，保留同名 `.meta`。如果图片边缘被裁得太多，把 `HotPotGame.ts` 中的 `IMAGE_CROP_X`、`IMAGE_CROP_Y` 调小；留白太多则调大。

### 背景图片

目录：`assets/resources/backgrounds/`

- `hotpot-bg.jpg`：整页静态背景，目标尺寸 `720 × 1280`；
- `hotpot-board.jpg`：棋盘内部静态插画，目标尺寸 `660 × 550`；
- `hotpot-corner.png`：右下角静态火锅，透明背景，目标尺寸 `512 × 512`。

覆盖文件时保持名称、格式和 `.meta` 不变。背景不要再加入动画雾气；如果图片自身画有烟雾，它会作为静态内容显示。

## 5. 手动更换音频

目录：`assets/resources/audio/`

| 文件 | 用途 |
| --- | --- |
| `bgm.mp3` | 背景音乐，首次触摸后循环播放 |
| `match.mp3` | 三消音效 |
| `win.mp3` | 胜利音效 |
| `lose.mp3` | 失败音效 |

直接覆盖同名 MP3 并保留 `.meta`。音量在 `setupAudio()` 和 `playEffect()` 的调用处调整，范围是 `0` 到 `1`。

## 6. 修改文字、颜色与按钮

- 页面固定文字都在 `HotPotGame.ts` 的 `buildShell()` 中，可搜索原文字直接修改。
- 文字通过 `makeLabel()` 创建，参数顺序为：父节点、文字、字号、颜色、位置、宽度、高度。
- 按钮通过 `makeButton()` 创建，参数中包含文字、位置、宽高、填充色和点击回调。
- 颜色使用 `#RRGGBB` 十六进制格式。
- 关卡名称在 `GameData.ts` 的 `LEVELS` 中修改。

## 7. 增加一种新食材

增加食材需要同时完成以下步骤：

1. 在 `IngredientType` 联合类型中增加英文标识。
2. 在 `INGREDIENTS` 中增加名称和颜色配置。
3. 在 `assets/resources/ingredients/` 放入同名 PNG。
4. 确认 `HotPotGame.ts` 的资源加载逻辑会遍历新的 `INGREDIENTS` 项。
5. 调整目标关卡的 `typeCount` 和 `typeOffset`，确保该食材位于本关最多 10 种的轮换窗口内。
6. 运行关卡验证脚本并逐关预览。

英文标识必须与图片文件名完全相同，并建议只使用小写字母、数字和连字符。

## 8. 检查 TypeScript

Creator 打开并完成一次资源导入后，可以在工程目录运行：

```powershell
cd D:\codeX\create\app\HotPot
node "C:\ProgramData\cocos\editors\Creator\3.8.8\resources\app.asar.unpacked\node_modules\typescript\bin\tsc" --project tsconfig.json --noEmit --skipLibCheck
```

命令没有输出且退出码为 `0`，表示 TypeScript 检查通过。最终效果仍需在 Creator 预览和微信开发者工具中各验证一次。

## 9. 修改后没有生效怎么办

按下面顺序排查：

1. 确认修改的是 `assets/` 源文件，不是 `build/` 内的产物。
2. 回到 Creator，等待右下角资源导入完成，再重新预览。
3. 在资源面板中右键修改过的资源，选择“重新导入”。
4. 关闭预览页后重新打开，不要只刷新旧浏览器标签。
5. 微信端必须重新构建，再在开发者工具中选择“清缓存 → 全部清除”后编译。
6. 仍然无效时关闭 Creator，删除可再生成的 `library/` 和 `temp/` 后重新打开工程；不要删除 `assets/` 或其中的 `.meta`。
