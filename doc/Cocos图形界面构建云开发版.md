# Cocos 图形界面构建微信云开发版

适用：Cocos Creator 3.8.8，分支 `codex/cloudbase-player-save`。

2026-10-30 修复：新版构建面板有时向字段校验传入扩展局部参数，旧扩展错误地将其当作完整构建任务，导致已导入配置仍被误报“发布包名称未设置”。项目扩展已更新为1.0.1：局部参数仅检查保护开关，完整任务仍做原有校验，实际构建前钩子始终检查目录、分支、AppID、引擎模块和包体。更新后重新加载扩展 / 构建面板；已有任务若实际输出名为 `wechatgame-cloud-dev-001`，仍需在基础设置中去掉后缀。无需反复导入配置，也无需关闭保护。

## 为什么截图中没有这个任务

`build/wechatgame-cloud-dev` 是此前命令行构建的输出目录，不是已经添加到 Cocos 面板的构建任务。面板里的 `wechatgame-001` 是原有任务。两者不是同一件事。

这次新增了项目扩展 `app/HotPot/extensions/hotpot-cloud-build`，并将 `app/HotPot/tools/wechat-cloud-dev.build.json` 补全为可导入配置。**任务仍需你在 Cocos 面板中导入一次**；没有直接修改正在运行的编辑器配置或伪造成功构建记录。

## 首次操作：新建并导入一次

1. 保存当前工程，重新打开项目或重启 Cocos，让它发现新加的项目扩展。若未加载，在「扩展 → 扩展管理器」的项目扩展中核对并启用「火锅云开发构建」（包名 `hotpot-cloud-build`）。该扩展是现成的 JavaScript，不需要 npm 安装或编译。
2. 打开「项目 → 构建发布」，点击截图顶部的 **「新建构建任务」**。保留原来的 `wechatgame-001` 任务。
3. 选择 **微信小游戏** 平台，进入构建选项页面。不是在旧任务卡片上直接点击构建。
4. 在构建选项页面顶部找到 **Import / 导入构建配置** 按钮，选择：

   ```text
   D:\codeX\create\app\HotPot\tools\wechat-cloud-dev.build.json
   ```

5. 核对导入后的关键设置：

   | 项目 | 应为 |
   | --- | --- |
   | 平台 | 微信小游戏 |
   | 发布路径目录 | 工程下的 `build` |
   | 发布包名称（实际输出目录） | `wechatgame-cloud-dev`，不能带 `-001` 后缀 |
   | 任务名 | 建议为 `wechatgame-cloud-dev`；任务名不会决定输出目录 |
   | 启动场景 | `assets/scene/main.scene` |
   | AppID | `wx943cc2d81ec6f820` |
   | 主包压缩方式 | 小游戏分包 |
   | MD5 Cache / 调试模式 | 关闭 |
   | 分离引擎 / 高性能模式 / 开放数据域工程模板 | 关闭 |
   | 保护旧发布目录 | 已勾选（扩展校验项） |

6. 点击 **构建**。任务创建后，构建任务列表才会显示 `wechatgame-cloud-dev`。首次构建如果失败，任务可保留用于修复后重试；不要把目录存在当作本次成功。
7. 查看构建日志，确认出现 `[HotPot Cloud Build] 完成`，且 Cocos 任务显示成功。

## 以后怎么打包

在同一个工程和分支中，打开「构建发布」，找到保存的 `wechatgame-cloud-dev` 任务，使用 **正常构建**，点击「构建」即可。无需关闭 Cocos 或运行 PowerShell。

输出目录固定为：

```text
D:\codeX\create\app\HotPot\build\wechatgame-cloud-dev
```

构建后由你在微信开发者工具中打开这个目录，进行模拟器或真机测试。构建扩展不会自动打开开发工具、上传小游戏、部署云函数或发布版本。

## 扩展会做什么

- 构建前校验开发分支、平台、输出目录、场景、AppID 和遮罩配置。GUI 校验不匹配时阻止构建，钩子中再次检查。
- 从 `doc/res/regions.json` 校验地区层级，生成客户端和云函数副本；生成云函数根目录的运行模块，并等待 Cocos 重新导入地区资源。
- 构建后写入 `game.json` 的 `cloud: true`、小游戏 AppID、云函数源码目录。
- 检查实际构建的云环境和 Mask / ScrollView 导出，写入启动构建标记，检查 4 MB 包体限制。

这些处理与原命令行构建共用逻辑；原命令行脚本仍可使用。构建配置会显式启用 Mask；项目 `settings/v2/packages/engine.json` 的默认配置也已启用 Mask，以覆盖编辑器预览。仅构建覆盖参数不能修复编辑器预览里的组件缺失。

修改了云函数代码或地区选项时，扩展只准备**本地**云函数文件。云端函数的部署仍按 [CloudBase 后台手动操作指南](CloudBase后台手动操作指南.md) 执行。新增字体未包含的地区文字时，还需先运行字体裁剪工具；常规游戏代码和文案修改无需这一步。

## 常见情况

- **还是只有旧任务**：新目录和新扩展不会自动添加面板任务；必须完成「新建任务 → 导入配置 → 构建」。不要编辑 `profiles` 文件来伪造任务。
- **找不到 Import**：先进入新建任务的构建选项页面；截图中的任务列表不是导入页面。
- **没有“保护旧发布目录”项，也没有扩展日志**：扩展未加载。先在项目扩展管理中核对并启用，再重新打开构建面板。不要继续用缺少扩展的配置出包。
- **提示旧发布目录受保护**：当前仍选中旧任务或没有导入完整配置；新建独立任务并导入上述文件。
- **新任务也显示“构建参数校验失败”**：点击 `wechatgame-cloud-dev` 卡片左下角的编辑按钮，检查“发布包名称”（实际输出目录名称），应精确为 `wechatgame-cloud-dev`。Cocos 可能将它保存成 `wechatgame-cloud-dev-001`，即使任务标题正确也会被保护校验拒绝。手动去掉 `-001`，保存后执行正常构建；不要重复新建任务。2026-10-20 已根据当前保存的任务配置复现该问题，修正输出名称并合并该任务已保存的微信平台参数后，校验通过。扩展现会在 Cocos 控制台输出 `[HotPot Cloud Build]` 和具体失败原因；重启编辑器或重新加载扩展后生效。旧 `wechatgame-001` 任务在本开发分支被拦截是保护行为，请使用开发任务。
- **提示分支不匹配**：当前应为 `codex/cloudbase-player-save`，不要在已申请发布的分支上使用这份开发配置。
- **Error 3804 / 地区列表空白**：核对导入配置里的 Mask 模块；修复后做正常构建。不能只重编译脚本，因为引擎模块也发生了变化。
- **点击图鉴报 `getComponent: Type must be non-nil`**：若调用栈指向 `makeCollectionScroll` 的 `addComponent(Mask)`，是预览引擎裁剪了 Mask。2026-10-26 已同时启用项目默认配置的 Mask 缓存值及 `includeModules`，保留其他引擎设置；并在图鉴/成就及地区入口先检查滚动组件，缺失时提示而不创建半屏遮挡。请保存并重启 Cocos，再重新打开预览，令预览引擎重新载入。微信开发者工具中的包需正常构建后再测试；无需因此更新云函数。
- **构建失败但目录仍存在**：其中可能是上一次的文件。以本次任务成功状态和扩展完成日志为准。
