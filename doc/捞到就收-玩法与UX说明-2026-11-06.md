# 锅里捞啥｜捞到就收道具副本开发交接

版本：三段翻倍与每小时一锅 · 2026-11-07

工程：`app/HotPot` · Cocos Creator 3.8.8 · TypeScript · 微信小游戏  
市井朱红、奶油黏土、青瓷雅韵、宣纸朱印均已接入副本、库存与第三关背包。切换皮肤时继续使用同一份本机库存和副本存档。

## 1. 要做什么

玩家从首页进入「道具」，点击「开捞」直接开始三段挑战。玩家用七格托盘三消清盘，前两段清空后可收下当前数量或继续挑战。结算时随机获得撤回、翻锅、炸弹，进入主线第三关可用的背包。

- 主线仍是现有三关，保留关卡内容、第三关局内道具及阶段奖励。副本入口放在首页菜单的「道具」页。
- 副本不使用道具。首版也不提供免费复活，避免掩盖实际难度和收锅选择；主线的复活规则照旧。
- 副本沿用现有组件、主题和安全区布局。第三关背包图标为四套皮肤各自绘制。

## 2. 首页菜单与页面

```text
首页菜单
├─ 我的
│  ├─ 我的位置 → 复用所在地选择与保存
│  ├─ 图鉴     → 复用普通／珍藏页签
│  └─ 成就     → 复用现有成就页面
├─ 道具
│  ├─ 撤回、翻锅、炸弹库存
│  └─ 开捞 / 继续捞锅 / 显示冷却倒计时
└─ 其他原有入口，如地域榜单、换肤、分享、游戏圈
```

「我的」「道具」为两个并列入口。把原本独立的首页图鉴入口及菜单里的所在地、成就入口迁入「我的」，删除重复入口和旧热区。保留首页标题居中；其他入口保持原来的功能。子页返回到它的直接上一级，例如图鉴返回「我的」，「我的」返回首页菜单。「道具」页显示「撤回 ×N」「翻锅 ×N」「炸弹 ×N」，库存为 0 时仍显示，另用一句话解释「赚到的道具可在第三关使用」。

首页的「道具」页可随时查看库存。只有主线第三关处于可操作状态时，才提供从当前棋局使用道具的按钮；在第一、第二关或副本中没有使用入口。进入副本前保存正在进行的主线对局；从副本返回后，主线牌阵、托盘、局内道具及复活状态保持原样。

## 3. 副本规则

开锅时在本机记录下一次可开锅时间，间隔 60 分钟。失败、结算和放弃都按开锅时的时间继续计算；暂停、跨天和重启可续玩原局。未结算时，优先显示「继续捞锅」。旧版已开局的玩家可按当时的牌阵和奖励完成该局。

| 段数 | 牌量与种类数 | 清空后可收的道具总数 |
| --- | --- | --- |
| 第 1 段 | 66 张 / 8 种 | 1 个 |
| 第 2 段 | 132 张 / 10 种 | 2 个 |
| 第 3 段 | 264 张 / 12 种 | 自动发放 4 个 |

每段独立生成牌阵，从空托盘开始。越往后层数越多、食材种类越多。棋盘与托盘都清空才算过段，且第七格恰好三消时先消除。每层由完整的三张组构成，从上到下有一条可解路径。

| 状态 | 文案和行为 |
| --- | --- |
| 段内游玩 | 显示「第 2 / 3 段」和「清空本段可收 2 个道具」，有七格托盘及暂停按钮。界面隐藏总牌量和剩余牌数。 |
| 非末段清空 | 同时显示现在收多少、下一段成功可收多少、失败得几个。两个按钮「收下 X 个」「继续捞」同等清晰，不倒计时、不默认选中。 |
| 暂停或稍后决定 | 保存当前牌阵、托盘或待选状态。再进副本回到原处，跨天也能续玩。 |
| 末段清空或主动收锅 | 一次发放对应总数的道具，展示实际种类和数量，提供「返回道具页」。 |
| 托盘满且无法三消 | 本轮失败，显示「本轮没获得道具，背包道具仍保留」。不能返回上一段补领。 |

清完第 2 段后，玩家可以现在收下 2 个，也可以继续捞。继续成功共得 4 个，失败本轮得 0 个。此前显示的 1 个、2 个都是可选的结算总数。退出会保存选择，主动收锅或清完末段才发放道具。

每个奖励分别从撤回、翻锅、炸弹中等概率抽取，允许重复。结算页按种类合并，例如「撤回 ×2、翻锅 ×1、炸弹 ×1」。奖励随本轮保存，重进结算页展示同一结果。

## 4. 第三关怎么用库存道具

第三关的「背包」图标沿用统一包身轮廓，市井朱红用红盖铜扣，奶油黏土用软陶和叶片，青瓷雅韵用青釉和莲纹，宣纸朱印用信封式翻盖和朱印。背包明确显示「库存」，与本局道具分开。每个主线第三关牌局最多用 **2 个库存道具**，三种共用上限。

1. 打开背包，选择一个库存道具。库存不足、次数上限、取牌或消除动画锁定、游戏已结束时不可用。使用前检查道具当前能否产生效果。
2. 第一次有效使用前提示「使用背包道具后，本局仍可通关，仅保存在本机，不计入地域榜单」。取消则原样返回。
3. 确认后，使用现有的撤回、翻锅、炸弹效果。成功才扣该类库存 1、增加本局用量并锁定「道具辅助」状态；无可撤回操作、无可炸目标或翻锅不能生效时不扣库存、不占次数。不能通过撤回退还库存、重置用量或恢复榜单资格。
4. 道具辅助局照常显示胜利或失败及后续操作；通关可记入本机统计。首版不把该局新增的通关或成就进度写入云端，也不加入地域榜单或离线上传队列。没用过库存道具的第三关仍按现有逻辑上榜，原有局内道具不影响这项资格。

## 5. 存档与接入要点

- **本机库存独立保存。** 按当前玩家身份隔离库存和副本存档，首版访客与已登录账号不自动合并。玩家文案注明「道具和副本进度仅保存在本机」。仓库迁移到另一台电脑开发，不代表玩家在设备之间同步库存。
- **副本独立于主线。** 开局与下一次可开锅时间一起写入本机存档。段号、牌阵种子与变化、托盘、状态和奖励明细与库存同存。取牌时先保存消除后的状态，再播放与主线共享的飞牌、让位、三消星芒和托盘收拢。清盘弹窗等末次三消播完再出现。重进已结算页只读结果。
- **库存扣减与棋盘效果一起落盘。** 首次成功使用前，从主线局进入独立的本机辅助续玩记录；保存同一主线对局 ID、牌阵、道具用量与辅助标记。每次扣库存与对应棋局变化使用同一提交边界，避免切后台后出现扣了库存却没生效，或生效但没扣库存。仅打开背包或确认取消不进入辅助状态。
- **榜单拦截放在数据入口。** 现有 `RegionLeaderboardService.setSave()` 会把第三关胜局加入待上传队列。副本与辅助局应走独立本机保存路径，不能把胜局交给这个方法，也不能把辅助局存档写进现有云同步。不能只在胜利弹窗隐藏榜单文案。后台恢复、云存档回包、换号或主线每日重置都要避免覆盖当前本机副本或辅助状态。恢复辅助局时重新读出使用次数和标记。
- **保持标准局兼容。** 原有云端标准局检查点保留在首次使用库存前，不能从云端恢复的旧检查点替换本机正在玩的辅助局。辅助局结束后回到现有主线流程，从下一次正常开局重新使用原来的保存和同步逻辑。旧存档无需补造库存或做云端迁移。

## 6. 开发顺序与验收

1. **验证副本闭环。** 检查三段清盘、收或继续、失败和冷却到期后的开局。用固定种子验证各段可解，并覆盖托盘第七张恰好三消。
2. **再接背包与菜单。** 先做两入口、库存展示、结算发奖和退出续玩，再接第三关消耗。复用现有主题和组件。
3. **最后验证本机与云端边界。** 先在 Cocos 预览跑通，再在微信开发者工具和手机检查恢复、布局与榜单。未做的验证在交付时标记为待验。

| 验收场景 | 预期结果 |
| --- | --- |
| 分别在三段收锅 | 道具总数依次为 1 / 2 / 4。允许同类重复，入账数等于结算展示数。 |
| 第二段清空后继续，第 3 段失败 | 本轮得 0 个，背包原有库存不变。 |
| 开锅 59 分钟内收锅、失败、放弃或重启 | 仍显示剩余冷却时间。开锅满 60 分钟且旧局已结束时可再次开捞。 |
| 停在段末选择页退出、隔天重进 | 仍停在原选择页；尚未选收锅时库存不增加。 |
| 结算按钮连点、结算后重启 | 一次入账，奖励明细一致，不能重抽或重复领取。 |
| 第三关用 2 个库存道具后重启，再尝试第 3 个 | 前两次各扣 1；重启仍为 2 / 2，第 3 次不可用，局内自带道具仍按原规则使用。 |
| 取消使用，或道具无法生效 | 库存与次数保持，榜单资格不变。 |
| 未使用库存道具的第三关通关；使用库存道具的第三关通关 | 前者按原流程上传；后者只记本机通关，不进离线队列，联网重试也不会补传。 |
| 有主线进度时进副本，再返回主线 | 同一主线棋局可续玩。副本不会改变主线进度、珍藏或地域统计。 |
| 四套皮肤、窄屏及刘海屏 | 「我的」「道具」可见可点，子页返回正确。七格托盘下方有「暂停」，两个段末选择按钮完整可见。 |
