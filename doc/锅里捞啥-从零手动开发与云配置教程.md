# 锅里捞啥：从零手动开发与云配置教程

本教程对应 Cocos Creator 3.8.8 和 2026-11-02 的代码快照 `24d2c13`。先在电脑上完成工程和预览，再在腾讯云控制台设置数据库、云函数和云存储，最后用微信开发者工具测试。每节的“完成后”可用来判断能否继续。

本教程附录提供完整代码和素材；本次编写没有替你更改云环境或发布小游戏。云控制台按钮名称可能随界面更新而变化，遇到不同名称时按功能寻找，不要凭猜测改变其他资源。

3. 准备本仓库的 [手动开发教程配套](手动开发教程配套)：其中有四份代码附录、素材文件夹和文件清单。源码目录为 `D:\codeX\create\app\HotPot`。
4. 下表是本工程已经写入源码的开发配置。只有确认使用这个小游戏和开发环境时才照填；不要将它当作你自己账号的通用示例。

| 项目 | 本工程的开发值 |
| --- | --- |
| 小游戏 AppID | `wx943cc2d81ec6f820` |
| 开发环境 ID | `cloud1-d2gc9q7cobffff893` |
| 玩家云函数 | `hotpotPlayerDev` |

## 2. 选择工程准备方式

已有完整仓库并只想学习或修改现有游戏：打开 Cocos Dashboard，点击“导入项目”，选择 `D:\codeX\create\app\HotPot`，用 3.8.8 打开。等待导入结束，在资源管理器双击 `assets/scene/main.scene`，进入第 5 节。现成工程已包含代码和素材，不必从附录再复制一遍。

想自己逐文件搭建：继续第 3、4 节。请使用新的练习目录，避免覆盖已有工程；下面以 `D:\HotPotManual` 为练习根目录。

## 3. 在 Cocos 中新建练习工程

1. 打开 Cocos Dashboard，选择 Creator 版本 **3.8.8**，点击“新建项目”。选择空的 **2D** 项目模板。
2. 项目名填 `HotPot`，保存位置选 `D:\HotPotManual\app`，创建并打开。实际项目目录应为 `D:\HotPotManual\app\HotPot`。
3. 打开“项目 → 项目设置”，找到设计分辨率，宽度填 `720`、高度填 `1280`。在引擎模块设置中确认启用 UI 所需的 `Mask` 和 `ScrollView`，保存设置。
4. 使用 Windows 文件资源管理器，在 `D:\HotPotManual` 下建立 `doc\res` 目录；将本仓库 `doc\res\regions.json` 复制进去，形成 `D:\HotPotManual\doc\res\regions.json`。后续云函数准备工具会从这里读取地区源文件。

**完成后：** Cocos 标题栏显示新建的 `HotPot` 工程；工程目录包含 `assets`、`settings`；地区源文件位于练习根目录的 `doc\res`。

## 4. 手动放入代码、素材和场景

### 4.1 创建代码文件

1. 在 VS Code 中选择“文件 → 打开文件夹”，打开 `D:\HotPotManual\app\HotPot`。
2. 打开 [01 数据层完整代码](手动开发教程配套/01-数据层完整代码.md)。按每个二级标题给出的相对路径创建文件，例如 `assets/scripts/data/CloudConfig.ts`；把该标题下面代码块的内容完整复制进去并保存。共 13 个文件。
3. 用相同方法完成 [02 客户端完整代码](手动开发教程配套/02-客户端完整代码.md)，共 33 个文件。
4. 按 [03 云函数完整代码](手动开发教程配套/03-云函数完整代码.md) 创建 `cloudfunctions/hotpotPlayerDev` 下的 16 个文件。附录包含为这个固定快照生成的六个共享 `.js` 和 `regions.json`。
5. [04 校验工具与工程设置](手动开发教程配套/04-校验工具与工程设置.md) 中的 `tools/` 文件是本地辅助工具；创建它们可供第 9 节使用。对新工程，先用 Cocos 图形界面设置分辨率和引擎模块；不要直接覆盖新工程的整个 `settings` 目录。
6. 回到 Cocos，等待脚本导入及编译完成；打开“控制台”，先处理红色错误。

每个代码文件只复制对应代码块的内容，不要复制标题或代码块边框。完整清单见 [文件清单.json](手动开发教程配套/文件清单.json)。新工程中脚本的 `.meta` 会由 Cocos 生成；不要复制原工程脚本的 `.meta` 来覆盖新工程生成的文件。

**完成后：** `assets/scripts/data` 有 13 个 TypeScript 文件，`assets/scripts/core` 有 33 个；Cocos 编译没有红色脚本错误。

### 4.2 导入图片、音频和地区数据

1. 打开 [配套素材目录](手动开发教程配套/素材)，其中有 `audio`、`data`、`game-ui`、`ingredients`、`reference` 五个文件夹。
2. 在 Cocos 的资源管理器找到 `assets`；如尚无 `resources` 文件夹，右键 `assets` 新建文件夹 `resources`。
3. 将上述五个文件夹拖入 `assets/resources`，保持子目录和文件名。也可用 Windows 文件管理器复制后切回 Cocos，等待导入。
4. 确认 `assets/resources/ingredients/food-a.png`、`food-b.png`，以及 `assets/resources/data/regions.json` 已出现。图片资源展开后应有纹理子资源；如没有，选中图片，在属性检查器中检查资源类型及导入状态。

**完成后：** 五个目录都出现在 `assets/resources`；Cocos 控制台没有素材导入失败。食材图集必须保持 5 列布局，文件名不要更改。

### 4.3 新建场景并挂载脚本

1. 在 Cocos 的资源管理器中新建 `assets/scene` 目录；右键该目录，创建场景并命名为 `main`，双击打开。
2. 如果场景没有 `Canvas`，在层级管理器右键创建 UI 画布 Canvas；确认画布下有 UI 摄像机。选择 Canvas，在属性检查器确认 `UITransform` 尺寸为 `720 × 1280`。
3. 在资源管理器找到 `assets/scripts/core/HotPotGame.ts`。选中层级管理器中的 Canvas，在属性检查器点击“添加组件”，搜索并添加 `HotPotGame`；也可以将脚本拖到 Canvas 的属性检查器。
4. 保存场景。点击顶部预览按钮，等待浏览器打开。第一次载入可能需要等待素材加载。

**完成后：** 预览出现“锅里捞啥”的棋盘，食材显示为图片，点击可放入托盘；打开“我的小馆”、图鉴、地区选项和页面换肤能看到界面。图鉴及榜单的列表可滚动。浏览器预览的云身份与微信身份不同，不能用它证明微信云存档已打通；云环境尚未就绪时先验证本地界面。

若添加组件时搜不到 `HotPotGame`，先检查 Cocos 控制台的第一条 TypeScript 错误，再确认脚本已保存、导入完成。若画面没有图片，检查 `resources` 的五个目录没有多嵌套一层 `素材`。

2. 选择并核对环境 ID：`cloud1-d2gc9q7cobffff893`。可以尝试 [本工程开发环境入口](https://tcb.cloud.tencent.com/dev?envId=cloud1-d2gc9q7cobffff893#/overview)。
3. 核对小游戏 AppID 是 `wx943cc2d81ec6f820`，并确认该小游戏与这个环境的关联、账号权限均正确。

**完成后：** 控制台显示开发环境概览，左侧可以进入数据库、云函数和云存储。旧环境 `hotpot-d9g7g17ifb99bdd1b` 是另一环境，本文操作以当前开发环境为准。环境列表为空时先核对登录账号和权限。

## 6. 手动创建数据库集合与权限

1. 在开发环境控制台左侧打开“数据库 → 文档型数据库”（也可能显示“数据库”）。
2. 若列表中已有 `hotpot_players_dev`，打开它并查看权限，不要重复创建或删除现有玩家数据。若不存在，点击“添加集合/新建集合”，名称填写 `hotpot_players_dev`，确认创建。
3. 打开该集合的“权限设置/安全规则”，选择 **仅管理端可读写**，有的界面称“无权限（ADMINONLY）”。若界面使用集合级规则编辑器，设置客户端读写均为 `false`，保存。云函数通过服务端身份访问，不需要开放客户端直接读写。
4. 同样检查或新建集合 `hotpot_config_dev`，权限也设为仅管理端可读写。这个集合用于可选的后台运行配置；缺失时函数会使用默认值。
5. 如需在后台调整隐藏入口点击次数，进入 `hotpot_config_dev`，点击“添加记录”，指定文档 ID 为 `runtime`，以数字类型添加 `collectionHeadingTaps: 6` 和 `collectionIngredientTaps: 3`，保存。若编辑器要求完整 JSON，可按下例填写；若 ID 是独立输入框，则 ID 填 `runtime`，JSON 内不要重复添加 `_id`。

```json
{
  "_id": "runtime",
  "collectionHeadingTaps": 6,
  "collectionIngredientTaps": 3
}
```

**完成后：** 两个集合显示在列表中，权限均为仅管理端可读写；可选配置文档的两个字段是数字。玩家集合在真实玩家首次成功调用 `load` 后才会出现其档案。配置项作用及取值见 [后台点击配置说明](50种食材与后台点击配置-2026-10-29.md)。规则对客户端请求的含义见 [腾讯云安全规则说明](https://cloud.tencent.cn/document/product/876/41802)。

## 7. 手动上传并部署云函数

### 7.1 准备本地文件和 ZIP

1. 找到要部署的函数目录：现有工程为 `D:\codeX\create\app\HotPot\cloudfunctions\hotpotPlayerDev`；新建练习工程为 `D:\HotPotManual\app\HotPot\cloudfunctions\hotpotPlayerDev`。
2. 对照 [云函数完整代码](手动开发教程配套/03-云函数完整代码.md)，确认目录内有 `index.js`、`handler.js`、`request-context.js`、`leaderboard.js`、`runtime-config.js`、`package.json`、`package-lock.json`、`config.json`、`settings.json`、`regions.json`，以及 `RuntimeConfig.js`、`GameConfig.js`、`GameData.js`、`PlayerTypes.js`、`RegionData.js`、`PlayerData.js`。
3. 打开 `settings.json`，确认 `enabled` 为 `true`，环境 ID、AppID 和集合名与第 1 节一致，`regionsFileId` 为空字符串。
4. 若修改过数据层 TypeScript、地区源文件或 `CloudConfig.ts`，先按第 9 节生成新的共享文件；附录里的生成文件只对应固定快照。现有工程也可先使用第 10 节的 Cocos 构建扩展生成本地文件。
5. 在文件资源管理器中**进入** `hotpotPlayerDev` 文件夹，选中以上文件，右键“发送到 → 压缩(zipped)文件夹”，命名为 `hotpotPlayerDev-upload.zip`。不要选中整个外层目录后再压缩。
6. 双击 ZIP 检查：打开第一层就能直接看到 `index.js`、`package.json` 和 `settings.json`。不要上传历史导出目录中的旧 ZIP。

### 7.2 在腾讯云控制台上传

1. 在第 5 节确认的开发环境中打开“云函数”。先看列表：有 `hotpotPlayerDev` 就进入该函数；不存在时点击“新建云函数”，函数名填 `hotpotPlayerDev`，类型选择事件函数/空白函数，运行环境选择控制台支持的 Node.js 版本，执行入口填 `index.main`，完成创建。
2. 在函数详情的“函数代码/代码”区域选择“上传 ZIP 包”或同等入口，选中刚才的 ZIP 并上传。确认没有把源码放进额外的一层文件夹。
3. 选择“保存并安装依赖”（界面可能显示“部署”并提供安装依赖选项），等待任务完成。依赖由函数根目录的 `package.json` 声明；观察安装日志，不能只看到上传完成就离开。
4. 在函数详情核对函数名、入口和运行环境。进入“日志”，确认部署没有模块缺失或依赖安装错误。

**完成后：** 函数列表出现 `hotpotPlayerDev`，部署和依赖安装成功。腾讯云关于 ZIP 根目录和安装依赖的操作可参考 [控制台部署云函数](https://docs.cloudbase.net/cloud-function/manage)。

控制台测试可输入 `{"action":"load"}`。后台测试通常没有真实微信调用身份，返回 `IDENTITY_REQUIRED` 可以是正常结果；这只说明身份检查生效，不代表游戏端读写已经成功。不要通过伪造 OpenID 测试。

## 8. 云存储：检查权限和可选文件

当前快照的 `regionsFileId` 是空字符串，客户端和函数都随包携带 `regions.json`。因此完成本教程的云存档**不要求上传地区文件**。

如需要检查或管理云存储：

1. 在同一个开发环境中点击“云存储/存储”，打开文件列表和权限设置。
2. 检查当前已有文件及规则。玩家档案在数据库里，不要通过公开云存储来解决数据库访问问题。
3. 需要把地区文件保存一份时，在文件列表中创建 `res` 文件夹，进入后点击“上传文件”，选择本仓库 `doc\res\regions.json`。完成后列表应出现 `res/regions.json`；选中文件可查看 File ID。
4. 保持私有文件只允许管理端访问。如果此环境专用于本教程且目前不需要客户端直接读写云存储，可在控制台权限设置选择仅管理端可读写，或在对应的存储规则编辑器设置 `read: false`、`write: false`。已有环境请先核对现有应用对存储的依赖，再改变全局规则。
5. 上传本身不会切换游戏的数据来源。若明确希望由云函数读取该文件，复制同一开发环境的完整 `cloud://...` File ID 到 `CloudConfig.ts` 的 `regionsFileId`，按第 9 节重新生成云函数文件，重新上传部署，再重建客户端；确认函数有该文件读取权限并测试地区列表。该路径需要实际联调。

**完成后：** 默认方案中，无需修改存储权限或填写 File ID；可选上传方案中能在控制台看到目标文件，且没有为整个存储开放不必要的客户端访问。控制台安全规则说明见 [CloudBase 安全规则](https://docs.cloudbase.net/rule/learn-rules)。

1. 打开自己的练习工程，确认第 4 节预览成功。点击“项目 → 构建发布 → 新建构建任务”，选择“微信小游戏”。

3. 点击“构建”，等待成功。在文件资源管理器打开 `build/wechatgame-manual`，用 VS Code 打开其中的 `game.json`，在顶层添加或核对 `"cloud": true`；保留已有字段，注意 JSON 逗号。
4. 打开该目录的 `project.config.json`，核对 `appid`；如需从微信开发者工具访问练习工程的云函数源码，添加顶层字段 `"cloudfunctionRoot": "../../cloudfunctions/"`。保存两个 JSON 后，在微信开发者工具导入该构建目录并编译。

**完成后：** 构建目录有 `game.json`、`project.config.json`；微信开发者工具能打开并运行游戏。每次重新构建都会可能覆盖输出目录，需再次核对这两个配置。本练习没有现有工程扩展的构建后校验，要自行核对包体大小和微信工具提示。构建面板操作可参考 [Cocos 构建发布面板](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/build-panel.html)。

## 11. 用真实微信身份验收云存档

1. 确认第 6 节集合权限正确、第 7 节函数部署成功、第 10 节打开的是刚构建的包。
2. 在微信开发者工具中编译游戏，打开“我的小馆 → 所在地选择”，选择一个地区并返回。进行几次游戏操作，等待同步；重新编译或重新进入后检查地区及对局是否恢复。
3. 返回开发环境控制台，打开 `hotpot_players_dev`。确认新增或更新了一条玩家文档；对照记录时间、`revision` 和 `state` 判断。不要手工改 `_id`、身份字段或随意单独改棋盘字段。
4. 在微信开发者工具的“预览/真机调试”中用同一微信账号打开，重复检查地区及存档；需要跨设备确认时，在另一台设备使用相同账号验证。
5. 打开云函数 `hotpotPlayerDev` 的日志，按操作时间核对是否有错误。榜单需要实际的第三关通关记录；空榜单本身不代表云函数失败。

**完成后：** 同一微信账号重新进入后能恢复已同步状态，数据库中有对应玩家文档，云函数日志没有对应错误。模拟器成功不能代替真机验证；浏览器访客和微信账号也不是同一身份。

构建、云函数部署、小游戏上传审核和正式发布是不同步骤。本文到测试为止；如要发布，继续按微信后台流程操作并核对目标版本。

## 12. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| Cocos 场景空白 | 是否打开正确的 `main.scene`，Canvas 上是否添加 `HotPotGame`，脚本是否编译成功 |
| 食材显示文字或缺图 | 检查 `resources/ingredients/food-a.png` 和 `food-b.png`，等待图片导入 |
| 图鉴空白或 Mask 错误 | 检查项目与构建任务的 Mask、ScrollView 引擎模块，重启编辑器后重新构建 |
| 找不到地区数据 | 检查 `assets/resources/data/regions.json`；不要只把文件上传到云存储 |
| `Cannot find module` | 检查 ZIP 根目录、六个生成的共享 JS 和云端依赖安装日志 |
| `DEVELOPMENT_ENV_REQUIRED` | 检查客户端、函数 `settings.json`、当前控制台的环境 ID 和集合名是否一致 |
| `IDENTITY_REQUIRED` | 后台测试可能缺少微信身份；从对应 AppID 的微信小游戏发起调用并查看日志 |
| 数据库无玩家记录 | 检查是否使用真实微信身份、函数是否部署、集合名是否匹配；看函数日志 |
| 地区选择后未恢复 | 核对是否完成云同步、登录的是同一账号，检查云函数和客户端的地区文件版本 |
| 构建成功但微信工具仍是旧版 | 确认导入的是本次输出目录，重新编译；检查构建时间，避免把旧目录当作新包 |

手动维护已有玩家文档前，请参照 [CloudBase 后台手动操作指南](CloudBase后台手动操作指南.md) 备份、处理版本号和同步冲突。不要把示例配置当作云端当前状态；云端状态应在控制台再次核实。
