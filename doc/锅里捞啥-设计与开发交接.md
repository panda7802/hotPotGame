## 2. 产品与技术结构

- 单机竖屏叠层三消，13 种食材、10 关、2～4 层，18～120 张牌；只可拿取未被覆盖的牌。
- 七格托盘，同类归并、三个消除；重开确认、胜负面板、切关、背景音乐和音效。
- 第三关起撤回、炸、洗牌各一次。没有后端、账号、存档、广告和付费；“+30”是反馈文字，没有积分累计系统。
- Cocos Creator 3.8.8 / TypeScript；UI 使用 `Node/Graphics/Label/Sprite` 动态创建，动画用 Tween，声音用 AudioSource。

| 文件（相对仓库根目录） | 用途 |
| --- | --- |
| `app/HotPot/assets/scripts/core/HotPotGame.ts` | 场景 UI、输入、运行状态、加载资源、动画、音频、道具 |
| `app/HotPot/assets/scripts/data/GameData.ts` | 食材、关卡、固定种子牌阵、覆盖关系、炸牌目标选择 |
| `app/HotPot/assets/scene/main.scene` | 入口场景；多数界面不在场景里手工摆放 |
| `app/HotPot/tools/validate-levels.cjs` | 关卡与炸牌规则检查，依赖本机 Creator 内置 TypeScript |
| `app/HotPot/tools/build-wechat.ps1` | 微信小游戏构建与开发者工具入口 |

## 3. 已确认的视觉设计

正式名称始终为 **锅里捞啥**。采用 A「烟火小馆」背景、B 手绘食材方向、D 蒸汽汤勺标题。

- 环境：红布、暖灯、奶油纸纹、棕色木桌、铜锅。两侧挂签与灯笼题字已画入背景图片。
- 中部：直接使用背景纸纹，不重新添加大块白底、双层边框或密集装饰。
- 食材：透明图片、不带盘子，强调颜色和轮廓；可点击牌保持原色，下层牌中性调暗。
- 牌面：奶油色面、浅棕侧边和轻阴影，保留立体叠层感。
- 托盘：七个木质凹槽；上方“托盘 x/7 · 三个相同食材自动消除”已按要求删除，不要重新加回。
- 按钮：红色重新开始、奶油色声音按钮，带高光、厚度和粗图标；道具显示名称与次数。
- 标题：透明图等比显示，加载失败时保留同文案的 Label。切勿重新使用含“唠”字的旧概念图。

## 4. 资源规范

资源路径均相对 `app/HotPot/assets/resources/`：

| 资源 | 当前用途及维护方式 |
| --- | --- |
| `backgrounds/tavern-bg.png` | 整页小馆背景；包含灯笼、两侧文字牌、右下筷筒。改这些装饰需改图 |
| `backgrounds/title-d.png` | D 版透明“锅里捞啥”；不要加红色矩形底，也不要拉伸 |
| `ingredients/handpainted-atlas.png` | 4×4 透明图集；从左到右、从上到下切格，前 13 格有内容，最后三格空白 |
| `ingredients/jzg.png` | **茶树菇**独立资源，覆盖图集第八格；保留旧 ID/文件名以避免破坏配置 |
| 其他单张食材 PNG | 图集失败时备用；单独替换它们不会改变正常加载的图集画面 |
| `audio/bgm、match、win、lose.mp3` | 背景、消除、胜利和失败声音 |

图集顺序：牛肉、虾、青菜、蘑菇 / 玉米、鱼片、鹌鹑蛋、旧金针菇（停用） / 肉丸、莲藕、番茄、豆腐 / 油豆腐、空、空、空。`HANDPAINTED_TYPES` 是切格顺序，不能随意与关卡食材排序同步重排。

`loadIngredientImages` 按实际宽高切格，边界取整，不假设图集一定是 2048 像素。茶树菇在默认和备用路径都用独立图片，默认不会加载旧金针菇。新美术需要真透明背景，留出安全边距，缩小到约 40～60 屏幕像素检查辨识度。

旧 `hotpot-bg/hotpot-board/hotpot-corner` 资源和部分旧绘制方法仍留在项目中，并非当前主界面的使用入口；不要因为看到它们就修改错文件。当前资源加载以 `buildShell` 和其调用链为准。

## 5. 布局和调整入口

设计尺寸 `720 × 1520`，坐标原点位于界面中心，Y 向上。短屏采用 `SHOW_ALL`，长屏采用 `FIXED_WIDTH` 并通过安全区及 spread 调整。不要只按一张手机截图的像素修改坐标。

| 元素 | 代码参数 |
| --- | --- |
| 标题中心 | `(0, 576 + topSpread)`；图片适配框最大 500×132，等比 |
| 关卡栏 | `y = 480 + topSpread` |
| 剩余/可拿数量 | `y = 422 + topSpread` |
| 棋盘 | `y = -36 + topSpread`，容器 680×830 |
| 托盘 | `y = -440`，木框 688×124，七格间距 94 |
| 道具 | `y = -556`，三个按钮横坐标 -224/0/224 |
| 临时提示 | `y = -619`，短暂显示后淡出 |
| 底部按钮 | `x = ±158`，`y = -676 - bottomSpread`，292×82 |

基础牌 110.4×91.2；八行布局缩放 0.82。牌内图片最大 105.6×87.2，托盘图片最大 80×72，始终等比。

第 3 关起的层偏移为 `(-28,-16)、(0,0)、(28,16)、(-12,8)`，相邻行水平交错 ±10。这是视觉错位，不是增加逻辑层数。修改位置后 `createLevel` 会重新计算几何覆盖关系，必须重跑边界与解法检查。

`GameData.ts` 的 `EIGHT_ROW_IMAGE_HEIGHT` 仍保留旧版较大图片的保守间距参考，不等于当前渲染图标高度；不要只改它而不检查八行的总高度。修改牌尺寸还需要同步检查 `createLevel` 中用于覆盖计算的尺寸及校验脚本。

外观入口：`drawFoodTile`（牌面），`drawTavernPanel`（木框/凹槽/按钮材质），`drawControlIcon`（重开/声音），`makeToolButton`（道具）。图标线宽目前控制图标 5、道具图标 6，后者在 0.7 倍节点内显示。

## 6. 状态和道具约束

`levelData.tiles[].removed` 同时标记已经拿进托盘或已被炸掉的牌；`tray` 是独立的食材类型数组。遮挡通过 `blockedBy` 中尚未移除的上层牌判断，不应只检查渲染节点。

- 撤回：保存上次拿牌前的托盘与已移除 ID；恢复后重建棋盘，每关一次。
- 炸：`selectBombTargets` 为纯选择函数，可注入随机数便于测试；只在至少三张的种类中随机，选六或三张，不修改传入数据。`useBombTool` 才执行删除、扣次数、刷新和结算。
- 洗牌：重新分配棋盘剩余牌的食材类型，不改变位置。炸、洗牌后均清除旧撤回记录。
- `locked` 防止动画过程重复操作，`gameEnded` 阻止结束后继续拿牌。保留 `canUseTool` 的检查。
- 托盘节点重建前会先脱离父节点，因为 Cocos `destroy()` 延迟至帧末；不要直接删掉这一步，否则动画可能选中旧节点。
- 移动中的食材放到 `foodTransitionLayer`，避免被棋盘和托盘遮住。

## 7. 每轮修改后的验收

1. 第 1、3、10 关：标题/挂签不遮牌；八行最顶和最底不越界；托盘与按钮不重叠。
2. 连续拿三个同类：正确归并、消除、补位；七格满时正确失败。
3. 炸：剩余 6+、3～5、不足 3 的分支；被遮挡牌可参与；无候选不扣次数；托盘不变。
4. 撤回与洗牌、炸交互：不恢复已炸掉的牌，不在动画中重复操作。
5. 重开确认、下一关、最后一关、声音开关及图标状态。
6. 短屏和长屏、设备安全区、图集加载失败的备用表现。
7. 运行关卡校验和 TypeScript 检查。微信发布前另做真机和包体检查。

已知限制：当前自动执行环境启动 Cocos 存在 GPU/权限错误，不代表用户电脑一定不能预览。最终实际画面、所有动画及微信真机仍需手工验收。保留原图和旧资源会增加包体，清理前先查资源依赖，避免误删备用图。
